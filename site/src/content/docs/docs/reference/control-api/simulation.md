| `POST /__kaanal/sim/plan`            | Starts a sizing plan of the system in force: `{ "target": { "multiple": 0.1 to 64 } or { "req_s" }, "profile"?, "seed"?, "scenario"?, "p99_ms"?, "error_pct"?, "budget_per_hour"? (dollars an hour of the priced nodes), "keep"? (node names the plan must not move), "max_steps"? (1 to 100, default 30) }`. `202 { "id", "state": "running" }` with `Location: /__kaanal/sim/runs/{id}`; the record has `kind: "plan"`, its `plan_steps` as they are taken and, when `done`, `plan` and `proposed_draft` (both stripped from the list). `400` for a bad body, target, limit, budget, `max_steps` or `keep` name; `404` for an unknown profile or scenario; then, in this order: `409 { "error", "id" }` while a run, sweep or plan is in progress; `429` while two draft builds, samples or skeletons are in progress (the route builds the applied text to check it); `409` with no applied text, or when the applied text is not the design in force (Apply it first); `409` with no system. The budget counts per-use prices at the visits of the target run: the verdict is judged again from the re-check's cost, and `budget_check` (`budget_micro_usd_hr`, `cost_micro_usd_hr`, `rejudged`) says what the plan shown costs against it and whether those prices turned `holds` into `over_budget`. A database-family walk takes at most 10 steps. **Cheapest (Step 9c-2):** `"cheapest": true` searches for the cheapest design found that holds the target (it may make nodes smaller; a node in `keep` is never changed) instead of the walk, and adds a provider section per other provider; `"time_limit_s"` (1 to 600, default 150; it bounds the searches only, split between them: half to the main search when a section runs, the rest equally, checked between runs; the re-check, the section pricing runs and the sweep run after it), `"run_cap"` (1 to 2000, default 200 runs per search) and `"providers"` (a list of `aws`, `gcp`, `azure`, or `["none"]`; default every other provider when the design has a provider class) are `400` without it ("needs cheapest"), as are a bound crossed, an unknown or repeated provider and one the design already uses. The record's `plan` then also has `cheapest_note` ("cheapest found within the limit, not proven cheapest"), `search` (`stop`: `exhausted`, `run_cap` or `time_limit`; `runs`, `elapsed_ms`, `limit_ms`, `run_cap`, `design_in_force_holds`, `notes`), `comparison` (when a provider section ran: `not_compared` `[{ provider, reason }]`, `rows` `[{ name, price_micro_usd_hr, unpriced, unpriced_nodes, holds, over_budget_micro_usd_hr?, outcome, rank? }]` holders first, `comparable`, and `conclusion`, the winner or why there is none), `providers` (`[]` when none ran; each `{ "kind": "answer", "provider", "plan", "info", "cost", "cost_note"?, "budget_check"?, "notes" }`, where `cost` is the section design's price with per-use prices at the visits of one run at the target and the section's verdict is judged again against the budget from it, as the main plan's from `verify.cost`, the notes ending "assumes wires, egress, data location and application are unchanged; on-demand price estimates", or `{ "kind": "skipped", "provider", "reason" }`, the reason naming the node: "no managed <flavor> class for <provider> in the price table", "no equivalent on <provider>" (no class big enough), "kept on <provider>, so a section on <provider> would mix providers" (a node in `keep` with a provider's class: a section is never a mixed design), "<node>: a cache on <provider> has no translation, so a section on <provider> would mix providers", "<node>: write flavor: to compare" (an Azure managed database with no `flavor` is not guessed onto AWS), "already on <provider>" or "nothing to translate") and `request.cheapest` (`time_limit_s`, `run_cap`, `providers` as resolved); `families` is `[]`. The proposed draft is the main search's design only: a provider section has no draft. Without `cheapest` none of these fields appear. |

| `GET /__kaanal/sim/runs/{id}`        | One run: `kind` (`run`, `sweep` or `plan`), `state` (`running`, `done`, `failed`), `generation`, `source`, `draft_rev` (the draft's `rev` for a draft run, else `null`), `profile`, `scenario`, `started_ms`, `finished_ms`, and `summary` or `error`. A sweep also has `sweep_points` (its points in run order, growing while it runs, emptied once it is `done` because `sweep.points` then holds them all, kept if it fails; `[]` for a run) and, once `done`, `sweep` (`label`, `limit` as `{ p99_ms, error_rate }` with the error rate a fraction, `points`, `verdict`, `recovers_at`, `stopped_at`, `first_to_saturate`, `dominant_cause`, `warnings`); a sweep also has `seed` (the body's, else the config's), `max_factor` (as checked), `fingerprint` (12 hex digits over the design files the build read: the design swept, not the chaos), `live_chaos` without a `scenario` (`{ scenarios, entries, digest }`: the chaos in force when it started; see [Simulation](/docs/guides/simulate/simulation/#load-sweep-where-does-it-break)), `chaos_digest` (12 hex digits over the compiled chaos it ran under, every sweep), `runtime_scenarios` when a scenario in force was defined through the API, and, for an inline profile, `inline_profile` (the posted profile; absent for a named one and for a run, and stripped from the list); a sweep has no `summary` or `cost`. A plan (`kind: "plan"`) has `plan_steps` (its steps as they are taken, kept after it is done; left out while there are none: before the first step, and for a plan that needed no step) and, once `done`, `plan` (`request`, `start`, `steps` with their `menu`, `end`, `verdict` as `{ kind }` where `kind` is one of `holds`, `already_holds`, `cannot_hold` (with `node`, which may be `null`, and `reason`), `over_budget` (with `over_by_micro_usd_hr` and `holds`: `holds: true` means the plan holds and costs the budget plus that much; `holds: false` means no holding design was found and the next step needed would cost the budget plus that much; the plan shown may itself cost more than the budget when the design in force already does, which `budget_check` says), `no_progress` (with `node`) or `step_cap`, then `families`, `unpriced_nodes`, `verify`, `measured_knee`, `price_before`, `price_after` and `words`: the report's sentences as plain text, `{ verdict, budget (null without a budget), sections }` with one sentence per provider section, `""` for a skipped one) and `proposed_draft`; money is in `micro_usd_hr`, millionths of a dollar an hour, and the label says the figures are estimates in dollars an hour. It also has `seed`, `fingerprint` and `chaos_digest` as a sweep. A plan has no `summary`. `409` on the report or draft of a plan that failed. `404` once pushed out of the last eight.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `GET /__kaanal/sim/runs/{id}/log`    | A page of the run's log sample: `{ "lines", "next", "total", "sampled": true, "note" }`. Query: `node`, `replica`, `endpoint` (`METHOD /path`), `level` (`info`, `warn`, `error`), `request` (a request counter, which is per stream, so pair it with `endpoint`), `limit` (default 200, at most 1000), `after` (index of the last line seen; `next` is the `after` of the next page, `null` at the end). `total` counts the stored lines before the filters. A line has `t_ms`, `level`, `request`, `stream`, `node`, `replica`, `event`, `wait_ms`, `service_ms`, `status`, `note`; `replica`, `wait_ms` and `service_ms` are `null` on a failure line (the engine does not record them), so a `replica` filter skips those. `400` for a bad `level` or `endpoint`; `404` for an unknown run; `409` while it runs, after it failed, or for a sweep or a plan (neither has a log). | `GET /__kaanal/sim/runs/{id}/report` | A finished sweep's or plan's report (its `kind` decides): `200 text/markdown; charset=utf-8` (a readable file ending in a re-run recipe and a `## Data` block of JSON), or with `?format=json` (`markdown` is the default) `200 application/json`, the same data alone. The same bytes on every fetch. A plan's report says first that it is not a prediction, then its target, the design in force, the steps, the menu per step, the database-family what-ifs, the verdict in plain words, the re-check of the proposed draft and the measured knee; its JSON is `report_version`, `label`, `id`, `plan` (the record's `plan`) and `recipe` (`kaanal sim plan ...` with the `=` forms, `seed`, `fingerprint`, `chaos_digest`, ...). A **cheapest** plan's report (Step 9c-2) adds the label "cheapest found within the limit, not proven cheapest", a `## Search` block (why it stopped, runs, time), a `## Comparison` table of the design in force and each provider what-if (holders ranked cheapest first with the winner named; "no design holds at any size tried, so there is no winner" when none does; skipped providers with the reason, listed first), the changes with each one's own price effect (never a running price), the verdict (a search cut by the run cap or time limit says none was found within the limit, never "cannot hold"), and one section per provider that carries "assumes wires, egress, data location and application are unchanged; on-demand price estimates"; the recipe adds `--cheapest --time=150s --run-cap=N --providers=...`. A plain plan's report is unchanged. `400` for another `format` or any other query key; `404` for an unknown or pushed-out id; `409 { "error" }` while it runs ("not finished"), for a failed sweep or plan (the error says why) and for a plain run (run reports are made in Studio); `500 { "error" }` for a done record missing a field every sweep or plan gets (a server bug: `the sweep record has no ...`, `the plan record has no ...`).
