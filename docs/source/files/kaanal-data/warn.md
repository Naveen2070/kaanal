# `crates/kaanal-data/src/warn.rs`

Warnings for schema keywords the generator does not honour.

## What it does

The generator ignores some JSON Schema keywords (`not`, `pattern`, `patternProperties`, `uniqueItems`, `multipleOf`) — generated values may violate them. Rather than staying silent, every ignored keyword becomes a one-line warning that `kaanal validate` and `kaanal up` print (rule R4.6).

## Items

| Item                                              | Kind  | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------- | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `IGNORED`                                         | const | The five keywords above (`discriminator` was removed in D1: it is honoured, and `discriminator_warnings` reports only the cases that cannot work). **Keep in sync with the generator**: if the generator learns one, remove it here.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `discriminator_warnings(m, endpoint, out)`        | fn    | **Private.** For a `discriminator` next to `oneOf`/`anyOf`: one warning per branch whose tag cannot be set (no mapping, which `api` turned into an `enum`, and no `enum`/`const` on the tag property: `discriminator 'petType' has no mapping, enum or const for oneOf branch 1; its tag is generated normally`), one per mapping key no branch carries (`discriminator mapping 'cat' names no oneOf/anyOf branch; it is never generated`), and one when `propertyName` is missing (`discriminator has no propertyName and is ignored`). Deduplicated per endpoint, so a schema reused under many properties warns once. A `discriminator` with no `oneOf`/`anyOf` gives nothing (R1.52).                                                          |
| `unsupported_keywords(schema, at) -> Vec<String>` | fn    | **Private.** One warning line per ignored keyword found. `at` names the endpoint (`"GET /users"`); nested properties are appended (`"GET /users .code"`). Property _names_ that happen to equal a keyword (a field called `pattern`) are never flagged — only actual keyword positions.                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `walk(s, at, out)`                                | fn    | Recursive walk: flags keywords on the current schema object, flags `maxLength` too small or `minLength` too large for a `format` value (uuid 36, date-time 20, date 10 — the format wins, rule R4.5), flags a `minLength` over the generator's `MAX_MIN_LENGTH` cap (10 000, R6.10d), flags a `minItems` larger than `maxItems` once per place (`minItems` wins, for generated arrays and a paged list's total), then recurses into `properties`, `items`, `additionalProperties`, `oneOf`/`anyOf`. An `allOf` schema is replaced by the generator's own `merge_all_of` result and walked at the same depth, so warnings match what is generated; a conflicting `type` gives one "allOf types conflict; first wins" warning per endpoint (R6.10a). |
| depth check                                       | —     | A schema nesting deeper than the generator's `MAX_DEPTH` gives one warning per endpoint ("deeper values are null"), however many branches go too deep.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `paged_array_warning(e, at)`                      | fn    | **Private.** A paged object response (`PageSpec::detect`) with more than one array property: one line naming the route and the property paging uses, and why (`the first in key order`, or `a list name wins over key order`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `ApiModel::warnings()`                            | impl  | Runs `unsupported_keywords` over every endpoint's inlined response schema, plus `paged_array_warning`, collecting all warnings. Called by the server's `check`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
