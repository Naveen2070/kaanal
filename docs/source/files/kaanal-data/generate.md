# `crates/kaanal-data/src/generate/`

The data generator: deterministic, realistic JSON from an OpenAPI 3.0 schema.

## What it does

`generate(schema, field, seed, &Options)` produces a `serde_json::Value` that validates against the schema and looks like production data (real names, emails, postcodes in the node's locale, not `"string"` / `0`). Same version, config, data files and seed give the same output, always.

An `allOf` is first merged into one schema (`merge_all_of`), then generated once. Pick order (D1.8, first match wins): **`example` → `examples` → `const` → `enum` → `oneOf`/`anyOf` → type**. For a scalar the type step is: **project dictionary → `format` → built-in dictionary → constraint defaults**. Specific beats general: a schema `example` or `enum` beats any dictionary, a project entry beats a `format`, a `format` beats a built-in guess by field name.

`Options` ([dataset.md](dataset.md)) carries the locale pack ([pack.md](pack.md)) and the dictionaries ([dictionary.md](dictionary.md)). Names, places, phones, currency and country come from the pack; field-name to generator mapping comes from the dictionaries.

## Public functions

| Function                                           | What it does                                                                                                                                                                                                            |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generate(schema, field, seed, &Options) -> Value` | Entry point. `field` is the property name this value is for (drives the dictionary lookup).                                                                                                                             |
| `apply_params(body, params)`                       | Copies URL path params into same-named top-level fields when types fit (`/users/42` becomes `id: 42`). Strings overwrite strings; numeric strings overwrite numbers; a non-numeric param never corrupts a number field. |

## Seeding model (rule R4.4)

- `stable_hash`: a private copy of core's FNV-1a (this crate cannot depend on core; the test `stable_hash_matches_core_algorithm` pins them identical with the same known-answer vector as core).
- `child_seed(parent, name, index)`: every child value derives its own seed. Adding or removing schema properties never changes the values of other fields (tested), below the `MAX_VALUES` budget: the budget is spent in key order, so near the cap a new property can turn later fields into `null`.
- `group`: the _enclosing object's_ seed. Fields that must agree (city, state, postcode, address; first name, last name, full name, email) derive their shared choice from `group`, not from their own seeds, so one object always describes one place and one person.
- A `oneOf`/`anyOf` branch is picked from the field's **own child seed** (`child_seed(seed, "branch", 0)`), never from a parent's or sibling's rng and never from `group`, so adding a property never changes a branch (R1.52a). `additionalProperties` keys use `child_seed(seed, "additionalProperties", 0)` the same way.

## Limits

- `MAX_DEPTH = 16`: pathological nesting returns `null` instead of recursing forever. Shared with `warn.rs`, which warns at startup when a schema nests deeper (R6.2). `oneOf` nesting counts too.
- `MAX_RANDOM_ITEMS = 20`: `maxItems: 1000000` cannot build a huge array (`minItems` is still honoured).
- `MAX_VALUES = 10_000`: values per body. Nested arrays multiply and `minItems` is honoured, so only a per-body budget bounds the size; past it, values are `null`. `const`, `additionalProperties` keys and `oneOf` branches each spend from the same budget. `value_bound(s, depth)` is the worst case `generate` can spend on `s` (the same walk with every array at its longest draw, the dearest `oneOf`/`anyOf` branch and three `additionalProperties` keys; capped at `MAX_VALUES`); paging divides `MAX_VALUES` by it to cap the records of one page (R1.62).
- `MAX_MIN_LENGTH = 10_000`: longest string a `minLength` can ask for (R6.10d). A larger `minLength` is capped and `warn.rs` warns at startup.
- Length limits are skipped only for formats the generator builds (`email`, `uuid`, `date-time`, `date`, `uri`, `url`, `ipv4`, `ipv6`, `hostname`, `byte`, `duration`); `password` is plain text and is fitted. Dictionary `pick`, `static` and `template` strings are never fitted either (R1.56).

## `pattern.rs` (D2)

An in-house sampler over `regex-syntax` (spec section 6.2). `compile(p)` parses once; `Err` means unsupported: lookaround, back-references or invalid syntax (rejected by the parser), or a shortest match over 1024 characters (`(a{1000}){1000}`). `cached(p)` keeps one `Compiled` per distinct pattern text for the process, so the mock path never recompiles. `Compiled::sample(rng, max_len)` draws a string from the field's seeded `ChaCha8Rng` with integer ranges only: literals as written, alternation uniform, repeats `min` plus at most 8 extra (fewer when `max_len` is short), classes restricted to printable ASCII (else any ASCII, else the class's own characters, e.g. `\p{Han}`), anchors and boundaries empty. `Compiled::is_match(s)` asks a one-keyword `jsonschema` validator, so "matches" means what the self-check means (ASCII `\w`, not the `regex` crate's Unicode `\w`).
`with_pattern(v, p, s, rng)` is called by `scalar_for` for a string with `pattern` after the project dictionary (a project `static`/`pick` is pinned and returned untouched; `example`, `const` and `enum` return before). The candidate from `format` / the built-in dictionary / the default word is kept when it already matches; otherwise up to 8 samples (seeds `child_seed(seed, "pattern", k)`, `seed` drawn from the field's own rng) are tried and the first matching one within `minLength`/`maxLength` wins. None fits: the candidate stays and `problem` has warned at startup. `fit_length` is never applied to a pattern value.

## `reconcile/` (D2)

After an object's properties are generated, `reconcile(obj, schema, seed, opts)` (called at the end of the object branch of `value_for`, and from `empty.rs` so the empty form keeps the same scalars, R1.53a) makes related fields agree. **Invariant: no shared rng stream.** A rule's values come from seeds derived from the field itself or are pure functions of values already present, so adding an unrelated property never changes another field, and the pass is idempotent. `is_pinned(ps, name, opts)` is true when the property schema has `example`, `examples`, `const` or `enum`, or a project dictionary entry for the name is `static` or `pick`; rules never rewrite pinned fields.

`time.rs` applies the time chains of spec 4.1. Built-in chains are slots of alias names (`updatedat`/`modifiedat`); the project adds chains and removes built-in ones through `Dictionary::chains()` and `chains_off()`. The first free member keeps its value; each later free member is `previous + (BASE_EPOCH - previous) * permille / 1000`, `permille` from that member's own seed (a quadratic skew toward small). Dates and date-times are parsed and written back in the shape they had; a chain mixing the two is skipped.

`person.rs` (spec 4.2): `age` and a birth date (`dateOfBirth`/`dob`/`birthDate`/`birthday`, a date, a date-time or a format-less date string) agree, where "age" is whole years to 2026-01-01. A free date is placed inside the year that gives exactly the `age` (day offset from the date's own seed; a date-time keeps its time of day), so a pinned `age` works too. With a pinned date, a free `age` is computed from it unless that breaks the `age` schema's `minimum`/`maximum`, in which case nothing changes. Both pinned, ages over 150, or only one field present: untouched. (Deviation from the first spec text: the date follows the age, not the reverse, so `age` keeps the value the dictionary gives it and the pass does not depend on how birth dates are distributed.)

`money.rs` (spec 4.3): applies only to an array of **line items** (an element with `price`/`unitPrice` and `quantity`/`qty`, or a line-amount field `lineTotal`/`amount`/`subtotal`), so `{items: [{name, price}], total: 3}` and a paged envelope keep their counts. One array is chosen (the only one, or the only one named `items`/`lines`/`lineItems`/`orderItems`/`products`/`entries`); a `null` element (body budget), an empty array, several candidates or a schema with mixed integer and number money fields skip the object. Free fields only: a line amount = price x quantity, `subtotal` = sum of the lines, `tax` = 0 to 20 percent of the subtotal (permille from the field's own seed), `shipping` from a four-value band (cents mode only), a `discount` above the subtotal is cut to it, `total` = subtotal + tax + shipping - discount. Arithmetic is exact: all-integer money uses checked `i128`; otherwise integer cents rounded half-even, written back with two decimals. Any value that does not fit its field's bounds or the mode's range is not written (and an unrepresentable line skips the whole object).

`Gen::Locale` and `Gen::Language` (spec 4.4) read the node's pack: `locale` is the pack tag (`en-IN`), `language` its primary subtag (`en`); they replace the old `language` pick.

## `multipleOf` and `uniqueItems` (D2)

`multiple.rs`: after a free number or integer is generated (and after `pattern`), `snap(v, ty, s)` moves it to the nearest multiple of `multipleOf` inside `minimum`/`maximum` (exclusive 3.0 booleans included). Decimals are integers scaled by a power of ten (up to 6 places), so `0.01` is exact cents and there is no float modulo; an integer field needs a whole step. If no multiple fits, or the step is unusable, the value stays and `problem(s)` is a startup warning. `example`, `enum`, `const` and project `static`/`pick` values are never moved.

`unique.rs`: for `uniqueItems: true` on an array whose `items` is a string, number, integer or boolean, `array_for` hands the elements to `dedupe`: a duplicate is redrawn from `child_seed(seed, "unique", i * 64 + k)` (k = 1..64, a slot of its own, so no neighbour's seed is reused) and dropped if all 64 collide. The array is therefore always unique and may be shorter than its random length; it is shorter than `minItems` only when the items have too few distinct values (an `enum`, a boolean, a bounded integer range), which `problem` warns about. Arrays of objects or arrays are not handled and keep a warning.

## `dist.rs` (D2)

Integer weighted tables and bucketed uniform draws, no `ln`/`exp`/`powf` and no `rand_distr`, so goldens are the same on every OS (spec 5). `pick_weighted` and `weight_of` match a value to `weights` by its JSON text and weigh unlisted values 1; `scalar_for` reaches them through a dictionary `pick`, and `value_for` through `pick_enum` for a spec `enum` (the project's entry first: one without `weights` turns the built-in weights off). `decade(lo, hi)` cuts a positive range at the powers of ten inside it and weights each bucket by its decade's weight (45/35/15/5, then 2, cheapest first) times the share of that decade it covers; a range from 0 or below is uniform. `bands(lo, hi)` draws one of four equal-width bands weighted 25/30/25/20. `recency_secs(window)` puts two draws in three in the last third of the window; `date_time(rng, days)` uses it (so `format: date-time` leans recent too). `money(...)` applies `dist` and `style` and falls back to the plain uniform value whenever the skewed or retail value would not fit the schema's bounds; `retail` changes the cents of the whole part.

## Review fixes (D2 whole-branch review)

- **Pinned means the generator the field got.** `is_pinned(ps, name, opts)` takes the property's own spelling (the dictionary matches suffix keys on its words) and counts a project `static`/`pick` only when it is the first entry that fits the field's type and bounds. A project `money` or `template` entry is a free value: it still meets `pattern` and `multipleOf` in `scalar_for`.
- **`can_hold(ps, v)`** (`reconcile/mod.rs`): every value a rule writes must fit the field's type and bounds, string lengths and `pattern`, and `multipleOf`; otherwise the generated value stays (a time-chain member then counts as fixed for the next one).
- **Chains** write each field at most once: a field placed by an earlier chain is fixed for a later (project) chain that mentions it. `parse` rejects month 13, day 99 and hour 25, so a pinned impossible date is not chained.
- **Birth dates.** `Gen::Date` takes `years: [min, max]`; the built-in `dateOfBirth`, `dob`, `birthDate` and `birthday` use `[18, 80]`: an age from the four bands, then a day inside that year (`text::birth_day`), so a birth date with no `age` beside it is an adult's. A `format: date` field takes that entry before the plain `date` format. A date-time birth date born on the base date's birthday is at midnight, so the age is exact to the second.
- **Money.** Everything is worked out before anything is written (an object is reconciled whole or not at all). Bare `total` is money only beside `subtotal`/`tax`/`shipping`/`discount` or when typed `number`; `orderTotal`/`grandTotal` always. When several arrays hold line items the one paging prefers (`items`, `data`, `results`, `content`, `records`) is used, else the object is skipped. A discount is capped at `max(subtotal, 0)`.
- **`multipleOf`.** All arithmetic stays within 1e15 units (a larger bound or step is a warning, never an overflow); float error in a bound (`1.1 * 100`) counts as the whole unit; a step that divides every integer (`0.5`, `1/n`) on an integer field is satisfied and says nothing.
- **`uniqueItems`.** A slot is redrawn up to 64 times; a redraw has a real value budget (so a `oneOf` item never becomes `null`); items equal by JSON Schema value (`1` and `1.0`) are duplicates; no `items` means plain strings.
- **Distributions.** A money range with `minimum` below 1e-6 is uniform (the power-of-ten walk would not end); the last allowed bucket reaches `maximum`; the four age bands are equal-width over the range (18 to 32, 33 to 48, 49 to 64, 65 to 80 for 18 to 80), not the spec's 18-29/30-44/45-59/60-80; whole-valued floats (`1.0`) weigh as `1`.
- **Patterns.** An open repetition makes up the length `minLength` still asks for; `problem` says "cannot be met" only after 4 seeds x 8 candidates all fail; the cache looks a pattern up before allocating its key; the sampler tracks the output length instead of recounting it.
