# `crates/kaanal-data/src/generate.rs`

The data generator: deterministic, realistic JSON from an OpenAPI 3.0 schema.

## What it does

`generate(schema, field, seed)` produces a `serde_json::Value` that validates against the schema and looks like production data (real names, emails, pincodes — not `"string"` / `0`). Same seed → same output, always.

An `allOf` is first merged into one schema (`merge_all_of`), then generated once. Field-pick priority (first match wins): **`example` → `enum` → `oneOf`/`anyOf` (first) → type**, and within a type: **`format` → field-name heuristic → constraints → fallback**.

## Public functions

| Function                                 | What it does                                                                                                                                                                                                      |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generate(schema, field, seed) -> Value` | Entry point. `field` is the property name this value is for (drives heuristics).                                                                                                                                  |
| `apply_params(body, params)`             | Copies URL path params into same-named top-level fields when types fit (`/users/42` → `id: 42`). Strings overwrite strings; numeric strings overwrite numbers; a non-numeric param never corrupts a number field. |

## Seeding model (rule R4.4)

- `stable_hash` — a private copy of core's FNV-1a (this crate cannot depend on core; the test `stable_hash_matches_core_algorithm` pins them identical with the same non-empty known-answer vector as core).
- `child_seed(parent, name, index)` — every child value derives its own seed. Adding or removing schema properties never changes the values of other fields (tested), below the `MAX_VALUES` budget: the budget is spent in key order, so near the cap a new property can turn later fields into `null`. Reordering is unobservable while `serde_json` has no `preserve_order` (keys are sorted).
- `group` — the _enclosing object's_ seed. Fields that must agree with each other (city/state/pincode/address) derive their shared choice from `group`, not from their own seeds, so one object always describes one place.

## Key internal functions

| Function                                           | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `value_for(s, field, seed, group, depth)`          | The recursive dispatcher implementing the priority order above. Depth-capped at 16. An `allOf` schema is merged and regenerated with the same seed and depth, so its parts share seeds (one person, one place). Object properties marked `writeOnly: true` are skipped silently (OpenAPI: request-only, R6.10b).                                                                                                                                                                                                                                                                                                                                                              |
| `merge_all_of(s) -> (Value, Vec<String>)`          | `pub(crate)`, also used by `warn.rs` (R6.10a). Merges the _schemas_: `properties` and `required` are unioned (a later property wins); every other keyword is first-wins, the `allOf` siblings counting first; nested `allOf` is expanded. A conflicting `type` keeps the first and is returned as a conflict for the startup warning. This changes seeded output for every `allOf` schema compared with the old per-part generation.                                                                                                                                                                                                                                          |
| `is_id(field)`                                     | `id`, `userId`, `ID`, `user_id`, `-id` → true; `valid`, `paid`, `android` → false.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `norm(field)`                                      | `firstName` / `first_name` / `first-name` → `firstname` for heuristic lookup.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `int_for(s, field, rng)`                           | Heuristic ranges: `age` 18–80, `quantity/qty/count` 1–10, ids 1–99 999, default 0–1000. `minimum`/`maximum` (and OpenAPI 3.0 boolean `exclusiveMinimum`/`exclusiveMaximum`) override the range, read by `int_bound`.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `int_bound(s, key, lower)`                         | An integer bound with its exclusive flag applied (R6.10c): `i64` as is, a `u64` past `i64::MAX` saturates, a float rounds inward (lower: exclusive ? `floor+1` : `ceil`; upper: exclusive ? `ceil-1` : `floor`), so `minimum: 0.0` counts as 0.                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `count(s, key, lower)`                             | `pub(crate)`. Reads `minItems`/`maxItems`/`minLength`/`maxLength` the same tolerant way: whole-number floats count, fractional ones round inward, negatives become 0. Also used by `warn.rs`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `number_for(s, field, rng)`                        | Default range by field name: `lat`/`latitude` 8–35 and `lng`/`lon`/`longitude` 68–97 (India) with 6 decimals; money-suffixed fields (`price`, `total`, `amount`, `cost`, `subtotal`) 99–4999 and everything else 0–1000 with 2 decimals. `minimum`/`maximum` apply to all of them, with one unit in the last place of slack for exclusive limits. A lone `maximum` below the default range moves the range down (as a lone `minimum` above it moves it up); an exclusive range narrower than one unit returns its exact midpoint unrounded; an infinite span (`-1e308..1e308`) returns the lower bound instead of panicking in `rand`. Unbounded lat/lng output is unchanged. |
| `string_for(s, field, rng, group)`                 | Dispatches on `format` (email, uuid, date-time, date, uri, ipv4) then `heuristic()`, then a lorem word. **Formats beat lengths** (rule R4.5): `fit_length` is skipped for formatted or well-formed heuristic values — a truncated email is worse than a violated `maxLength`.                                                                                                                                                                                                                                                                                                                                                                                                 |
| `heuristic(f, id_like, group, rng)`                | Field-name dictionary: names and emails (via `person(group)`, so `firstName`/`lastName`/`name`/`email` agree), `+91` phones, city/state/pincode/address (via `place(group)`), country/currency (India/INR), timestamps, descriptions, `status: active`, `*url` fields (`avatarUrl` → `https://example.com/avatar/N`, a bare `url` → `https://example.com/N`, one suffix stripped), id-like strings → uuid. Returns `None` when nothing matches.                                                                                                                                                                                                                               |
| `email`, `uuid`, `digits`, `sentence`, `date_time` | Value builders. `uuid` sets the v4 variant/version bits; `date_time` is always within the 365 days before 2026-01-01 (`BASE_EPOCH`, fixed so output never drifts between runs); emails use `example.com` only (rule R5.7).                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `civil_from_days(z)`                               | Days since epoch → (year, month, day); Howard Hinnant's algorithm.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `fit_length(v, s)`                                 | Applies `maxLength` (truncate) and `minLength` (pad with `x` in one pass, capped at `MAX_MIN_LENGTH`) to plain strings only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `array_for(s, rng, seed, group, depth, budget)`    | Length in `minItems..=maxItems`; the default `minItems` is `1.min(maxItems)`, so `maxItems: 0` gives `[]`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

## Limits

- `MAX_DEPTH = 16` — pathological nesting returns `null` instead of recursing forever. Shared with `warn.rs`, which warns at startup when a schema nests deeper (R6.2).
- `MAX_RANDOM_ITEMS = 20` — `maxItems: 1000000` cannot build a huge array (`minItems` is still honoured).
- `MAX_VALUES = 10_000` — values per body. Nested arrays multiply and `minItems` is honoured, so only a per-body budget bounds the size; past it, values are `null`. Array lengths are cut to the budget after the random draw, so seeds stay stable.
- `MAX_MIN_LENGTH = 10_000` — longest string a `minLength` can ask for (R6.10d; the value is an open question in `RULES.md`). A larger `minLength` is capped and `warn.rs` warns at startup.
- Length limits (`minLength`/`maxLength`) are skipped only for formats the generator builds (`email`, `uuid`, `date-time`, `date`, `uri`, `url`, `ipv4`); unknown formats such as `password` still get them.
