# `kaanal-sim/src/lib.rs`

The simulator's public API: the second driver of the core cost model (R2.5). `run` feeds open Poisson streams through a `Topology` and its compiled `Endpoints` on a virtual clock. Every service time comes from `kaanal_core::execute`'s plan, exactly as in live mode; the simulator replays it with fork/join and FIFO queueing, bounded queues and rate limits at nodes with `concurrency`, `pool` or `rate_limit`.

| Item                                         | Kind   | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Stream`                                     | struct | One stream on a compiled endpoint: `endpoint_key` (live format `"GET /users/{id}"`, part of the seed) and `rate_per_s` (exponential gaps). Any compiled endpoint can be a stream, static ones included.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `SimConfig`                                  | struct | `streams`, `duration` (arrivals stop here; in-flight requests finish), `warmup` (not reported), `seed` (the config's `seed:`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `run(topo, endpoints, chaos, cfg)`           | fn     | Validates, then simulates. Deterministic. Chaos is fixed for the whole run; it is one keyed `ChaosState` layer set (node, endpoint and node-at), validated with `first_error` and then compiled with `ChaosState::compile()` (a single layer).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `run_effective(topo, endpoints, chaos, cfg)` | fn     | Like `run`, but the chaos is already compiled: an `&EffectiveChaos` such as `ChaosStack::compile` gives for stacked scenarios plus live chaos (B2b-1). Validates the streams and bounds but not the chaos entry limits: the caller validated them (R6.9, each layer on entry).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `SimReport`                                  | struct | `requests` (after warmup, arrival order) and per-node `nodes` stats. `errors_by_kind()` counts failed reported requests by `status`, `reset`, `malformed`, `timeout` (kinds with none are absent).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `RequestRecord`                              | struct | `stream`, `n`, `arrival`, `latency` (service + waits), `result`, and the hops that ran, in plan order, each with its queue wait: `start` is the actual offset from arrival; a hop whose branch a failure cancelled is cut at the failure instant (absent if it had not started). Equals `execute()`'s hops at zero load.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `NodeStats`                                  | struct | `completed` own (non-`Net`) hops that started (a cancelled hop that began at the failure instant held its slot, so it counts though the record drops it), `mean_wait`, `utilization` (busy slot-time in the window ÷ slots × window, ≤ 1; 0 for unlimited nodes), `max_queue`, `limited` and `overflowed` (hop starts refused at this node by its rate limit, 429, or by a full queue, counted for reported requests whose answer they decided) (longest queue seen when a request joined at or after warmup; a queue that only drains after warmup is not counted), `timed_out` (deadlines that fired at this node: `timeout:` spans only, over reported requests; a hang that runs to its planned 504 shows as a `timeout` in `errors_by_kind` but is not counted here). |
| `validate`                                   | fn     | **Private.** Rejects: no streams, or more than 65 535 (`MAX_STREAMS`); (in `run` only) a chaos entry (any key: node, endpoint, node-at) that `ChaosState::first_error` finds invalid (the live limits, R6.9; ordered, so the same entry is named every run: `latency_add` over 5 min, `error_rate` outside 0–1, `error_status` outside 500–504; the lowest node id is named); rate not in 1e-6..=1e6/s (or NaN); an `endpoint_key` that is not a compiled endpoint (`stream 0: unknown endpoint '…'`); zero duration, warmup ≥ duration, duration > 365 days; duplicate keys; the R6.13 budget; a node (proc, ops, cache hit/miss costs) or edge latency that can sample over 10 h (named in the error). Overload (ρ ≥ 1) is allowed.                                      |
| `MAX_HOP_RECORDS`                            | const  | **Private.** R6.13: 20 000 000. Expected reported (post-warmup) arrivals × the most hops each stream's chain can take (`Seq::hops`, repeats included), summed over streams. A record costs about 100 bytes per hop plus a few hundred per request, so the cap bounds a run near 2–3 GB. Error: `workload too large: about N arrivals with up to M hops in total (max 20000000); lower the rate, the duration or the chain length`. A start value; tune once measured.                                                                                                                                                                                                                                                                                                      |
| `MAX_SIM_HOPS`                               | const  | **Private.** 50 000 000. A CPU bound: expected arrivals **including warmup** × the most hops of each stream's chain, summed over streams (about 0.35 µs per hop in release, so roughly 20 s at the cap). R6.13 bounds memory (post-warmup records); this bounds time, since pre-warmup requests are still simulated. Error: `simulated work too large: about N hops in total, warmup included (max 50000000); lower the rate, the duration, the warmup or the chain length`. A start value; tune once measured.                                                                                                                                                                                                                                                            |
| `MAX_STREAMS`                                | const  | **Private.** 65 535. A request tag packs the stream index into 16 bits, so more streams are rejected, never truncated.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `worst_case_secs`                            | fn     | **Private.** Largest value a `Dist` can sample: fixed value, lognormal cap, or 10 × the exponential mean.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `MAX_SERVICE`                                | const  | **Private.** 10 h: the 1 h config cap times the 10× tail cap.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

Each stream runs the chain compiled for its endpoint. Cache hops hold a slot at the cache node; `parallel` branches fork and join, `repeat` and `cache` steps are replayed as sampled.
