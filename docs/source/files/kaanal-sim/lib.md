# `kaanal-sim/src/lib.rs`

The simulator's public API: the second driver of the core cost model (R2.5). `run` feeds open Poisson arrival streams through a `Topology` on a virtual clock. Every service time comes from `kaanal_core::execute`, exactly as in live mode; the simulator only adds FIFO queueing at nodes with `concurrency`.

| Item                    | Kind   | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Stream`                | struct | One endpoint: `entry` (owning service or monolith), `op`, `endpoint_key` (live format `"GET /users/{id}"`, part of the seed), `rate_per_s` (exponential gaps).                                                                                                                                                                                                                                                                                                                                 |
| `SimConfig`             | struct | `streams`, `duration` (arrivals stop here; in-flight requests finish), `warmup` (not reported), `seed` (the config's `seed:`).                                                                                                                                                                                                                                                                                                                                                                 |
| `run(topo, chaos, cfg)` | fn     | Validates, then simulates. Deterministic. Chaos is fixed for the whole run.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `SimReport`             | struct | `requests` (after warmup, arrival order) and per-node `nodes` stats.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `RequestRecord`         | struct | `stream`, `n`, `arrival`, `latency` (service + waits), `result`, and each hop with its queue wait.                                                                                                                                                                                                                                                                                                                                                                                             |
| `NodeStats`             | struct | `completed` own hops, `mean_wait`, `utilization` (busy slot-time in the window ÷ slots × window, ≤ 1; 0 for unlimited nodes), `max_queue` (longest queue seen when a request joined at or after warmup; a queue that only drains after warmup is not counted).                                                                                                                                                                                                                                 |
| `validate`              | fn     | **Private.** Rejects: no streams; a chaos entry that `NodeChaos::validate` rejects (the live limits, R6.9: `latency_add` over 5 min, `error_rate` outside 0–1, `error_status` outside 500–504; the lowest node id is named); rate not in 1e-6..=1e6/s (or NaN); entry not a service; zero duration, warmup ≥ duration, duration > 365 days; duplicate keys; > 2 000 000 expected arrivals; a node or edge latency that can sample over 10 h (named in the error). Overload (ρ ≥ 1) is allowed. |
| `worst_case_secs`       | fn     | **Private.** Largest value a `Dist` can sample: fixed value, lognormal cap, or 10 × the exponential mean.                                                                                                                                                                                                                                                                                                                                                                                      |
| `MAX_SERVICE`           | const  | **Private.** 10 h: the 1 h config cap times the 10× tail cap.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
