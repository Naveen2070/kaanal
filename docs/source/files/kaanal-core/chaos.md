# `crates/kaanal-core/src/chaos.rs`

Chaos state types: the live, user-controlled failure knobs. The whole model (kinds, merge, keys) is explained in [../../chaos.md](../../chaos.md).

## What it does

Holds the _current_ chaos settings as sparse **layers** under a **key** (a node, an endpoint, or a node reached through one endpoint). Written by the control API (`PUT/DELETE /__kaanal/chaos...`), read by the chain executor on every request, which resolves the layers that apply to a visit into one dense `NodeChaos`. Everything here is runtime state — none of it comes from `kaanal.yaml`.

## Items

| Item                                                                  | Kind   | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------------------------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NodeChaos`                                                           | struct | The _resolved_ chaos for one visit: `latency_add`, `error_rate` (0.0–1.0), `error_kind`, `error_status`, `down` (hard outage: every visit fails with 503 regardless of rate).                                                                                                                                                                                                                                                                                                                                                           |
| `MAX_LATENCY_ADD`                                                     | const  | 5 min (300 000 ms): the longest `latency_add`. A typo like 1e12 ms would otherwise hang every live request or overflow the simulator's clock.                                                                                                                                                                                                                                                                                                                                                                                           |
| `HANG_CAP`                                                            | const  | 60 s: how long a `hang` holds a visit when the node has no `timeout:`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `ErrorKind`                                                           | enum   | The _input_ kind: `Status` (default), `Reset`, `Hang`, `Malformed`. `parse(&str)` / `as_str()` use the lower-case names.                                                                                                                                                                                                                                                                                                                                                                                                                |
| `FailKind`                                                            | enum   | The _outcome_ kind carried by `Fail`, `ChainResult::Err`, `Failure` and `Finished`: `Status`, `Reset`, `Malformed`, `Timeout`. A `Hang` ends as `Timeout`. `as_str()` gives `status\|reset\|malformed\|timeout` (trace, `error_map` keys, simulator breakdown).                                                                                                                                                                                                                                                                         |
| `NodeChaos::validate()`                                               | fn     | The one set of chaos limits (rule R6.9): `latency_add` ≤ `MAX_LATENCY_ADD`, `error_rate` within 0–1, `error_status` within 500–504 **for every kind** (4xx belongs to pins and cycle states, not random chaos). Returns a message naming the first bad field.                                                                                                                                                                                                                                                                           |
| `NodeChaos::default()`                                                | impl   | All-off defaults: zero latency, 0% errors, kind `status`, status 503, `down: false`. An all-default entry is _inert_.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `ChaosLayer`                                                          | struct | The same five fields as `Option`s: "not set by this layer" is `None`. `From<NodeChaos>` sets all of them. `validate()` checks only the fields that are set (same limits). `apply(&patch)` overwrites every field the patch sets (how a control-API merge works).                                                                                                                                                                                                                                                                        |
| `merge(&[&ChaosLayer]) -> NodeChaos`                                  | fn     | Folds layers, least specific first (Z11): latencies add (saturating), rates combine as `p + r - p*r` (one set rate comes back bit-for-bit), `down` ORs, last kind and last status win; defaults apply once at the end. `merge_iter` (private) is the same over an iterator so `resolve` needs no heap.                                                                                                                                                                                                                                  |
| `ChaosKey`                                                            | enum   | `Node(NodeId)`, `Endpoint(String)` (the route key, `"GET /orders"`), `NodeAt(NodeId, String)`.                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `ChaosState`                                                          | struct | The three maps (`nodes`, `endpoints`, `node_at`, private). `is_empty()` is the executor's fast path (one check per hop). `set(key, layer)`, `insert(node, NodeChaos)`, `layer(&key)`, `remove(&key)` (exactly that key; true when there was one), `clear()`, `resolve(node, endpoint) -> NodeChaos`, `endpoint(key) -> Option<&ChaosLayer>`, `entries()` (sorted: nodes by id, endpoints by name, node-at by id and name), `first_error()` (the first layer failing `validate`, in `entries()` order, so the message is deterministic). |
| `FromIterator<(NodeId, NodeChaos)>`, `From<[(NodeId, NodeChaos); N]>` | impl   | Keep the old "map of node → chaos" call sites compiling.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

`resolve` borrows (the node-at map is probed by `&str`), so a probe allocates nothing. It merges the node layer then the node-at-endpoint layer; the endpoint-wide layer is **not** in it — it applies once at the front door and is read with `endpoint()`.

## Invariants

- Every driver validates before anything lands here (the control API on the merged layer, the simulator on its whole `ChaosState` through `first_error`); the executor trusts the values.
- The executor reads this through a `std::sync::RwLock` held in `AppState` (see [server-state.md](../kaanal-server/state.md)); the `Arc` snapshot is B2b.
