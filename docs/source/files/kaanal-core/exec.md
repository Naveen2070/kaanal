# `crates/kaanal-core/src/exec/`

The chain executor — the heart of the engine. Given a request, it computes _what the request would experience_: every hop with its start and duration, and where (if anywhere) it fails.
Sizes per call (RULES 65): `Walk::bytes` is the pair in force; `call_step` swaps in a call's `sends` and `returns` and restores the caller's; `walk.rs` has `Counted` and `counted(node kind, hop kind, op)`, the table of which body a size cost counts (write: request, read and scan: response, a service: both; a database op or a storage first byte goes by the op), and `link` adds `Topology::header_bytes` to every wire transfer and `own` to the per-KB cost of an HTTP `Proc` hop. Two files (R3.8): `mod.rs` holds the public types (`Op`, `Hop`, `Plan`, `ChainOutcome`, `ChainRequest`), `execute`, `sample_plan` and the failure helpers; `route.rs` holds one `call:` step as a method (`call_step`, moved out of `walk.rs`) and a load balancer's pick of a callee (`pick_callee`: `pick_replica` over its wires, a callee with every copy down skipped, the round-robin counter its own and per copy); `walk.rs` holds the walk itself (its `pick_dynamic` emits a `PlanItem::Pick` for `least-conn` and `p2c`, carrying per-copy chaos latency as `skew`) (`Walk`, `Flow`, the per-hop draws, spans, forks and branch probability).

## What it does

`execute()` walks an endpoint's compiled chain (see [chain.md](chain.md)) as a **timeline**, sampling distributions and applying chaos at each node. It is **pure**: no sleeping, no IO. The live server samples a `Plan` and runs it on the engine actor (`mock.rs`, `actor.rs`); the simulator replays the returned `Plan` in virtual time (rule R2.5: one cost model, two drivers).

## Replicas in the walk

A node with `replicas > 1` is entered through one replica, picked by [`pick_replica`](balance.md) with the edge's `balance` over the node's own. The pick happens at the entry node (its own `balance`, since it has no calling edge), at every `call` repetition and at every cache lookup, before the call's span opens. The chosen replica covers the callee's whole body: its net hop, its `proc` and `op` hops and its inline work carry the same `Hop::replica`, while a call to another node picks that node's replica; `parallel` branches inherit the runner's. Round-robin advances per pick (`Walk::picks`), so two calls to one node take consecutive replicas. The replica never enters a seed: service times are the same for 1 or N replicas, so the simulator and the mocks agree. A node with one replica is always 0 and makes no pick. When every replica is down the call fails with a 503 at its start (`Walk::no_replica`); down replicas arrive with replica chaos.

An auth node that validates locally (no gateway-to-auth edge) runs its work inline in the gateway's sequence. That work takes a replica of the auth node picked once per sequence, never the gateway's; `Walk::own_replica` decides it, with `seq` told who the running node is. A cache with no live replica is a miss (it looks up replica 0, whose chaos is down), not a failure (Z17).

## Payload cost `ChainRequest::req_bytes` and `resp_bytes` (0 by default, so nothing changes) size the bodies. A call over an edge with `bandwidth` and bytes in a direction plans a `Link` hop of `bytes * 1e9 / bandwidth` ns (capped at 10 h): the request one inside the callee's span, before its net hop; the response one after its body (not after a failure). A node with `per_kb` adds `per_kb.sample() * (req + resp) / 1024` to its `proc` hop (or its `op` hop, for a database), once per body, from its own `perkb` draw so no existing draw moves. No bandwidth and no `per_kb` means no extra hop and no extra time. The queue behind a busy link is the engine's job (a plan holds only the zero-load transfer).

Connection set-up (RULES 68): `exec/conn.rs` is the pure theory (`handshake_rtts`, `rounds`, `stalls`: integer arithmetic, with the RFC 9293, 8446, 5246, 6928, 5681 and Cardwell 2000 sources in its header and a theory test per formula). `link.rs` holds `opens_connection` (one `conn` draw in `keepalive`, none when `net` is zero), `connect_request` and `connect_response` (the `Connect { resp }` hops); `route.rs` and the cache step in `walk.rs` call them around `net_sample` / `net_hop`. `HopKind::is_wait` is the one place that says which hops are only time passing.

## Link chaos`exec/link.rs` holds the link helpers (`link`, `shake`, `link_drop`, `link_fail`, `cache_miss_on_drop`). For a call over an edge with chaos (`EffectiveChaos::link`): `link_drop` first (a partition is a hang; otherwise one roll from `draw_rng(rep_path, target, b"link")`, drawn only when the link has a failure rate); a reset is a 502 `Fail` at the call, a hang is a `Net` hop of the callee's `timeout` (else `HANG_CAP`) then a 504 `Fail`, the shape of a node hang. It is a `Net` hop, not a `Link` hop, so a dead link does not hold the link's FIFO slot. Then the `Link` hop uses `min(bandwidth, bandwidth_cap)`, and the `Net` hop gets `latency_add` and jitter (`draw_rng(rep_path, target, b"jitter")`, uniform in plus or minus `jitter`, clamped at 0). A cache edge never fails the request: a dropped lookup is a miss (`cache_miss_on_drop`). With no link chaos nothing is drawn and the plan is as before. The engine needs no chaos input: the plan carries the capped transfer and the long hop.

## Walking a chain

| Step                  | What happens                                                                                                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Proc` / `Op`         | The node's own hop: chaos roll, then its cost (`proc`, or `ops[op]`). `Op` steps use the step's own op, else the op inherited from the call or endpoint (E10).                    |
| `Call`                | `repeat` times, in sequence: a `Net` hop on the edge, then the callee's body. A step `op:` applies to that call only.                                                             |
| `Cache`               | `repeat` lookups: a `Net` hop, then a hit or miss hop. A **hit ends the enclosing sequence only** (the callee's body, or the endpoint chain at the top) and that repetition only. |
| default-chain `Cache` | Skipped for writes (`reads_only`), so writes never touch the cache.                                                                                                               |
| `Parallel`            | All branches start together; the block ends with the slowest branch.                                                                                                              |

A down or failing cache is **fail-open** (E9, D12): it is charged its `miss` cost plus `latency_add`, recorded as `CacheMiss`, and the request carries on.

## parallel, fail-fast and the plan

Every branch is sampled to its own end or failure, even when a sibling failed earlier: the simulator needs the full tree because, under queueing, another failure may win. The earliest failure (by its hop start) decides the result; equal instants go to the lowest branch index. Nothing after a failed block is sampled.

The sampled tree is a `Plan`: a flat, pre-order list of `PlanItem`s — `Hop`, `Fail`, `Fork { branches, size }`, `Branch { size }`, `Hold { node, replica, size }` (sizes count the items after the marker; a `Hold` covers the body of a node with `hold: call` and slots, and is emitted by `Walk::open_hold` / `close_hold` in front of a `Call` and around the entry node's chain). `Plan::cancelled_by(fail)` lists the plan ranges a failure cancels (every sibling branch at every enclosing fork); live mode and the simulator share this rule.

## Spans, kinds and endpoint chaos (B2a)

Full model: [../../chaos.md](../../chaos.md).

- **Spans.** A `Call` to a node with a `timeout` is wrapped in `PlanItem::Span { node, timeout, at, size }` (pre-order, size-prefixed like `Fork`; `size` is fixed up after the body is walked, also when it failed). The root chain gets a span for `Endpoint.entry_node` when it has a `timeout`. A cache step gets none. Spans are transparent for hop order in `Plan::cancelled_by`, `visible`, the engine's step-over of cancelled siblings and the server's trace.
- **Kinds.** A chaos `reset` / `malformed` plans `Fail { kind }` at the hop start; a `hang` plans one own hop of the node's `timeout` (else `HANG_CAP`, 60 s) then `Fail { kind: Timeout, status: 504 }` at its end. `fail_of(kind, status)` maps input kind to outcome kind. No extra RNG draw: the existing roll `u` goes to `Resolved::hit(u)`, which returns `down` as status 503, else the first banded fault whose cumulative bound exceeds `u` (a single fault is exactly `u < rate`, as in B2a; several are banded, S8).
- **Cache.** A cache never fails the request (fail-open): a lookup slower than the cache's `timeout` is a miss charged exactly the timeout; a hang is a miss charged the timeout or `HANG_CAP`.
- **Endpoint chaos.** Resolved before the chain from its own RNG path. A failure is a `Fail` at offset 0 on the entry node; `latency_add` is a leading `HopKind::Delay` hop on the entry node.
- **Chaos lookup.** `execute`, `sample_plan` and the walk take `&EffectiveChaos` (the compiled stack, see [chaos.md](chaos.md)). Each visit calls `EffectiveChaos::visit(node, endpoint key)`, one borrowed lookup that already folds the node and node-at-endpoint layers, never a per-hop merge; an empty state costs one `is_empty` check per hop. The front door reads `endpoint(key)` once.
- **`execute` stays the zero-load oracle (Z13).** It does not run the engine; `deadline_failure` finds the earliest span whose body ends after its deadline (end = the latest `start + dur` in its range) and compares it with the planned `Fail`; a tie goes to the planned `Fail`. A deadline outcome is `Err { node: span node, status: 504, kind: Timeout }`, `fail` is the span's plan index, and all hops are clipped at the deadline instant (`visible(.., cut_all)`). Limits are still ignored.

## Visible hops and total

`ChainOutcome.hops` is what the client saw: plan hops except those a failure cancelled before they started; a cancelled hop that was running is cut at the failure instant. `kept[i]` is the plan index of `hops[i]`, `fail` the plan index of the deciding `Fail`. `total()` is the end of the latest visible hop — on a failure, the failure instant.

## Draws (R1.34)

Every hop has its own RNG: `HopRng::seed_from_u64(stable_hash(path, node name, tag))` ([rng.md](rng.md); SplitMix64 since 2026-10-25, `ChaCha8Rng` before), tags `net`, `proc`, `op`, `cache`, `prob` (a call step's branch draw, from the first repetition's path; `prob: 1` draws nothing) and `endpoint` for front-door chaos (its own path, so adding endpoint chaos re-seeds nothing else, Z15). `path` starts as `stable_hash(seed, endpoint key, n)` and each `call`/`cache` step repetition extends it with `(target name, occurrence, repetition)`. Own hops draw the chaos roll first (always), caches the chaos roll then the hit roll (always), then the duration — so chaos never shifts a timing. Guarantees (tested in `semantics.rs`): inserting a step leaves other steps' draws unchanged; swapping `parallel` branches with different targets changes nothing; two calls to a shared body draw independently because the parent path is chained.

## What changed from A1

One RNG per request became one RNG per hop, so exact sampled values differ from A1 (R1.34; no test pinned a sampled value, so nothing was re-pinned). Callees below the entry (monoliths, caches, external APIs) are now charged. Hops carry `start`, so `total()` is the latest end rather than the sum of durations.
