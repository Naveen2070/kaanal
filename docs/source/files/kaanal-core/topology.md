# `crates/kaanal-core/src/topology.rs`

The topology graph: nodes, edges, and all semantic validation of the config.

## What it does

`Topology::build` turns a parsed `Config` into a validated graph the executor can walk: at most one gateway and one auth node, the caller → dependency edge table, no unknown, self or duplicate edges, no cycles, and op/cache costs completed from flavor presets. Anything the executor would silently ignore or misinterpret is **rejected at load** with a named error (rule R1.23, R1.24, R2.7, R6.1).

## Error places

`TopologyError::located(cfg)` returns a `Located` (path + message) so `kaanal validate` can print `file:line:col`. `UnknownNode` points at the `from`/`to` name in its edge; `SelfLoop`, `DuplicateEdge` and `ForbiddenEdge` and `BadProb` (an edge `prob` outside 0 to 1, for configs built in code) at the edge entry; `Cycle` at the edge that closes it; `SecondGateway`, `SecondAuth`, `MissingOps`, `MissingCache` and `MissingGatewayEdge` at the node key; `NoEntry` at `nodes`. See [diagnostics.md](diagnostics.md).

## `Topology::build` checks, in order

Field placement (`ops` on a service, `spec` on a gateway) is not checked here: each node kind has its own strict struct, so it is a parse error in [config.md](config.md).

1. **Per node:** op costs complete, presets fill gaps (databases always; monoliths when they set `ops` or `flavor`; private `ops_of` via [presets.md](presets.md)) → `MissingOps`. Cache costs complete (`hit_ratio`, `hit`, `miss`, or a flavor) → `MissingCache`. A second gateway → `SecondGateway` (names the second one); a second auth node → `SecondAuth` (same).
2. **Somewhere to enter:** with no gateway there must be at least one service, monolith or auth node → else `NoEntry` ("a topology needs a gateway, a service, a monolith or an auth node (requests enter there)"). A lone gateway is fine (it answers static routes), and so is a lone auth node (a frontend plus its login mock, X11).
3. **Per edge:** both endpoints exist → `UnknownNode` (reports which edge number); not a self edge → `SelfLoop`; not a repeated caller → dependency pair → `DuplicateEdge`.
4. **DAG** — `check_cycles` is an iterative DFS with 3-colour marking (0 unvisited / 1 on path / 2 done) and an explicit stack, so a long chain of services cannot overflow the call stack (R6.12). Revisiting a colour-1 node reports the cycle as a readable path (`cycle: a -> b -> a`). It runs before the edge table so a cycle is reported as one.
5. **Edge table (R1.24)** → `ForbiddenEdge`, whose message lists what the caller may call:

| Caller                              | May call                                                           |
| ----------------------------------- | ------------------------------------------------------------------ |
| `gateway`                           | `service`, `monolith`, `auth`                                      |
| `service`, `monolith`               | `service`, `monolith`, `database`, `cache`, `external-api`, `auth` |
| `auth`                              | `service`, `monolith`, `database`, `cache`, `external-api`         |
| `database`, `cache`, `external-api` | nothing (leaves)                                                   |

6. **Reachability:** with a gateway, a service or monolith with an OpenAPI `spec` but no edge from the gateway → `MissingGatewayEdge` (its routes would never be walked).
