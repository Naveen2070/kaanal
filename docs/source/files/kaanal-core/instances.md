# `crates/kaanal-core/src/instances.rs`

Cloud instance presets (step 8P, RULES 102 b, 110). For users: [../../../web/nodes.md](../../../web/nodes.md#cloud-instances-instance).

## What it does

One embedded table of cloud instance types, `data/instances.csv` (`name,vcpu,memory_mib,net_mbps,usd_micro_hr`, sorted, `#` lines are comments), parsed once into a sorted `Vec<Instance>`. Every type of AWS, Azure and GCP, about 3,300. `instance: provider/type` on a node fills `cpu.cores`, `bandwidth` (both ways) and the `memory.limit` the node leaves out: `NodeConfig::cpu()` and `bandwidth()` fall back to it, `NodeConfig::memory()` takes its limit from it. A value the node writes wins. Your own machines are in [machine.md](machine.md).

The csv is generated by `scripts/gen-instances.mjs` from the public catalogues at instances.vantage.sh. **Every figure is an estimate** and an upper bound: a vCPU counts as a full core, burst credits are not modelled, a preset is capacity, not speed. `net_mbps` is the stated peak for AWS, the documented 2 Gbit/s per vCPU (cap 32, E2 16) for GCP, for Azure the figure Microsoft states on the size's own page (`scripts/azure-network.csv`, kept by hand, about 260 sizes; a constrained-vCPU size takes its parent's), and `0` where the source gives none (other Azure sizes, old AWS types): `net_bytes_per_s()` is then `None` and the card stays unlimited.

## API

| Item           | Kind   | What it does                                                                                                                                                                                         |
| -------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Instance`     | struct | `name`, `vcpu`, `memory_mib`, `net_mbps`, `price_micro_usd_hr` (the default region's on-demand Linux price an hour in micro-USD, 0 = none); `net_bytes_per_s()` (`None` for 0) and `memory_bytes()`. |
| `all()`        | fn     | Every type, sorted by name (also what `GET /__kaanal/instances` serves).                                                                                                                             |
| `lookup(name)` | fn     | The instance, case-insensitive and trimmed; `None` when unknown (binary search).                                                                                                                     |
| `hint(name)`   | fn     | For the load error: how many types the provider has and a few that start like the name.                                                                                                              |

An unknown name is a load error at `nodes.<name>.instance` (`config/machine.rs`).

## Tests

`instances::tests` (sorted, unique, every row has a CPU and memory, all three providers in numbers, lookup, well-known shapes); `tests/config/instance_memory.rs` (what an instance fills, a written value wins, the refusals); `draft_http/payload.rs` (the served table matches `all()`).

## Prices by region (RULES 121)

`src/prices.rs` reads `data/prices/<provider>/<region>.csv` (one file per region, about 220, 3.3 MB, `name,usd_micro_hr`, only types that have a price there, sorted), embedded through the generated `src/prices_data.rs` (`FILES`). `regions(provider)`, `region_table(provider, region)` (parsed on first use, then kept) and `price_micro_usd_hr(region, name)` (binary search). `DEFAULT_REGIONS` (AWS `us-east-1`, Azure `us-east`, GCP `us-central1`) is the region whose price is also the last column of `instances.csv`. Money is an integer in micro-USD so a sum does not drift. Estimates: on-demand Linux list prices as the catalogue carried them on the date in each header. A custom instance's `cost_per_hour` is checked in `config/machine.rs` (0 to 1,000,000 dollars).

`tests/instances_data.rs`: the Azure figures are the ones the pages state, a constrained size inherits and an unlisted one has none, the published list prices, price linear in size inside an AWS family, every region file sorted, a region's price differs from the default, and the default region's file equals the instance table's price column.
