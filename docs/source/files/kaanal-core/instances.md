# `crates/kaanal-core/src/instances.rs`

Cloud instance presets (step 8P, RULES 102 b, 110). For users: [../../../web/nodes.md](../../../web/nodes.md#cloud-instances-instance).

## What it does

One embedded table of cloud instance types, `data/instances.csv` (`name,vcpu,memory_mib,net_mbps`, sorted, `#` lines are comments), parsed once into a sorted `Vec<Instance>`. Every type of AWS, Azure and GCP, about 3,300. `instance: provider/type` on a node fills `cpu.cores`, `bandwidth` (both ways) and the `memory.limit` the node leaves out: `NodeConfig::cpu()` and `bandwidth()` fall back to it, `NodeConfig::memory()` takes its limit from it. A value the node writes wins. Your own machines are in [machine.md](machine.md).

The csv is generated by `scripts/gen-instances.mjs` from the public catalogues at instances.vantage.sh. **Every figure is an estimate** and an upper bound: a vCPU counts as a full core, burst credits are not modelled, a preset is capacity, not speed. `net_mbps` is the stated peak for AWS, the documented 2 Gbit/s per vCPU (cap 32, E2 16) for GCP, and `0` where the source gives none (Azure, old AWS types): `net_bytes_per_s()` is then `None` and the card stays unlimited.

## API

| Item           | Kind   | What it does                                                                                       |
| -------------- | ------ | -------------------------------------------------------------------------------------------------- |
| `Instance`     | struct | `name`, `vcpu`, `memory_mib`, `net_mbps`; `net_bytes_per_s()` (`None` for 0) and `memory_bytes()`. |
| `all()`        | fn     | Every type, sorted by name (also what `GET /__kaanal/instances` serves).                           |
| `lookup(name)` | fn     | The instance, case-insensitive and trimmed; `None` when unknown (binary search).                   |
| `hint(name)`   | fn     | For the load error: how many types the provider has and a few that start like the name.            |

An unknown name is a load error at `nodes.<name>.instance` (`config/machine.rs`).

## Tests

`instances::tests` (sorted, unique, every row has a CPU and memory, all three providers in numbers, lookup, well-known shapes); `tests/config/instance_memory.rs` (what an instance fills, a written value wins, the refusals); `draft_http/payload.rs` (the served table matches `all()`).
