# `crates/kaanal-core/src/config.rs`

Parsing of `kaanal.yaml` into typed config.

## What it does

Defines the serde types that mirror the YAML file, plus `Config::from_yaml` which parses and reports errors as `file:line:col: message` (rule R6.1 — the caller prepends the file name). `nodes:` is a map of `type`-tagged nodes (rule R1.15): each kind is its own struct with `deny_unknown_fields`, so a field on the wrong kind (or a typo) fails at load instead of being silently ignored. Single values are checked here (ranges, `p50 ≤ p99`, URL shape); every type also derives `schemars::JsonSchema`, from which the editor schema is built ([schema.md](schema.md)).

## Types (YAML shape)

```yaml
version: 1 # Config.version — must be 1
seed: 42 # Config.seed — RNG seed, default 0
port: 8080 # Config.port — default 8080
nodes: # IndexMap<String, NodeConfig> — insertion order preserved
  gw: { type: gateway, flavor: nginx, proc: 1ms, concurrency: 8 }
  app: { type: service, spec: openapi.yaml, proc: 2ms, concurrency: 4 }
  mono: { type: monolith, spec: openapi.yaml, proc: 3ms, flavor: mysql, ops: { read: 1ms }, concurrency: 2 }
  db: { type: database, flavor: postgres, ops: { write: 9ms }, pool: { size: 10, queue: 5, overflow_status: 504 } }
  cache: { type: cache, flavor: redis, hit_ratio: 0.8, hit: 1ms, miss: 2ms, ttl: 30s, concurrency: 32 }
  pay: { type: external-api, proc: 50ms, error_rate: 0.01, rate_limit: { rps: 100, burst: 20 }, proxy: "https://api.example.com", pool: { size: 4 } }
  login: { type: auth, proc: 5ms, token_ttl: 2h, concurrency: 2, claims: { aud: my-app }, users: [{ username: alice, password: secret, roles: [admin], scopes: [read, write], claims: { email: a@x.dev } }, { username: bob, password: pw }] }
edges: # Vec<EdgeConfig>
  - { from: app, to: db, net: 1ms, calls: 2 }
determinism: controlled # Config.determinism — `controlled` (default) or `realistic`
# Config.endpoints — a path to an endpoints file, or an inline map (EndpointsConfig)
endpoints:
  "GET /health": { override: { status: 200, body: { ok: true } } }
  "GET /orders/{id}": { op: read, chain: [ { cache: c }, db ], error_map: { db: 503 } }
```

## Notes

**Non-text passwords.** `password` is read by `password_text`, which accepts any scalar: serde alone would reject `password: 4711` (the node enum buffers values, so the number arrives as an integer) with a message that quotes the value, placed at the node key. A number, boolean or null becomes a private `NOT_TEXT` marker plus its kind, and `check_auth` rejects it at the value (`must be text, not a number (put it in quotes)`), never quoting it. Lists and maps fail with a fixed message. Text with leading zeros (`007`) stays text. `check_auth` runs in `Config::from_yaml` after serde, because a `deserialize_with` error inside `users[i]` would be placed at the start of `users:`. It checks reserved claim names, claim value types, the limits (32 claims/roles/scopes, 256-byte texts, 1000 users), empty usernames and scope characters (RFC 6749), each as a `Located` error at its own key or value. Messages never quote a password. `token_ttl` stays a field deserializer (whole seconds, 1 s to 1 day) because node-level field errors are already placed at their value.

Steps, `parallel` branches, `error_map` values and `endpoints:` are read by hand-written serde visitors (no `untagged`, no buffering), so serde keeps the position of a malformed step; semantic checks (unknown nodes, missing edges, limits) happen in `chain::compile`. `routes:` fails with `routes: was replaced by endpoints: (see docs)` at the key.

This file only _parses_ and checks single values. Field placement (`ops` on a service, `spec` on a gateway) is now a parse error, since each kind has its own strict struct. Semantic validation (edge table, optional gateway, DAG, ops that presets must complete) lives in [topology.md](topology.md); route/spec wiring happens in [state.md](../kaanal-server/state.md). Errors inside a node are positioned at the start of `nodes:` by serde for now.

User-facing field reference: [nodes.md](../../../web/nodes.md). Every node a chain reaches is charged; see [endpoints.md](../../../web/endpoints.md).
