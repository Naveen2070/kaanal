# `crates/kaanal/src/lifecycle.rs` (private)

Is an instance running, and how to start one in the background and stop one: the lock-based liveness check, the `run.json` reader, the stop path of `down`, the stop signals, and the pieces of `up -d`. Every function takes the state directory (`.kaanal`) as an argument, so the unit tests use a temp dir. User-facing description: [../../../web/lifecycle.md](../../../web/lifecycle.md).

## Liveness: the lock decides

`.kaanal/lock` is held (exclusively, for the life of the process) by a running `up`. The OS drops it when the process ends, however it ends. `probe` opens the file and tries to take it **shared**:

- success: nobody is running (`Probe::Free`, which keeps the shared lock in a `Guard` so a new `up` cannot take the exclusive lock between the probe and what the caller then does, such as deleting stale state);
- `WouldBlock`: an instance holds it (`Probe::Running`);
- any other error: an error (exit 1). It is never read as "stale": acting on a guess could delete a live instance's state.

Shared, because two probes must not make each other look "running"; `up` retries its exclusive lock for about 200 ms (`lock_at` in `main.rs`) so a probe never makes it report "already running". A `run.json` with no lock file at all gets a lock file created, so the caller still has a guard to hold.

## Items

| Item                                                                        | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Liveness`, `lock_probe(dir)`                                               | `Running` or `Free` for callers that do not need the guard.                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `Run`, `Startup`, `read_run(dir)`                                           | The parsed `run.json`: `addr` (host defaults to `127.0.0.1` for older files), `token`, `pid`, and the `startup` object (`auth`, `seed`, `warnings`; none of it secret). Any malformed piece gives `None`; unknown fields are ignored.                                                                                                                                                                                                                                                                                            |
| `read_run_wait(dir, budget)`                                                | `read_run` retried every 100 ms: the file appears a moment after the lock is taken. `STARTUP_WAIT` is 5 s.                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `remove_stale(dir, token)`                                                  | Deletes `run.json` only if it still holds `token` (a newer instance may have replaced it).                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `require_instance(dir)`                                                     | What every remote command (`call`, `follow_logs`) starts with. Free + file: `kaanal is not running (removed stale state from a stopped instance)`, exit 2. Free + unreadable file: removed, exit 2. Free + none: `(no .kaanal/run.json)`, exit 2. Held: the `Run`, or exit 1 `kaanal is starting or its state file is missing` after 5 s. Nothing is deleted while the lock is held.                                                                                                                                             |
| `transport_failure(dir, addr, why)`                                         | The failure for a request that got no answer. Lock held: exit 1 `kaanal is running (pid N) but its control API did not answer: why`. Lock free: exit 2 `kaanal is not running on ADDR: why`, and the stale file is removed. A probe error is returned as is.                                                                                                                                                                                                                                                                     |
| `clear_stale(dir)`                                                          | What `down` and `up -d` do first. `None` when the lock is held (nothing touched). Otherwise removes the stale file and returns the line to print: `kaanal is not running`, `... (removed stale state from pid N)`, `... (removed stale state)` or `... (removed unreadable state)`.                                                                                                                                                                                                                                              |
| `wait_lock_free(dir, budget)`                                               | Polls the lock every 50 ms until it is free. A probe that fails counts as not free, so `down` never says "stopped" on a guess.                                                                                                                                                                                                                                                                                                                                                                                                   |
| `run_or_gone(dir, budget)`                                                  | `down`'s way to get the `Run`: each round runs `clear_stale` first, so an instance that exits meanwhile is `Found::Gone(line)`, not an error; a file that never appears under a held lock is exit 1.                                                                                                                                                                                                                                                                                                                             |
| `PidCheck`, `verify_pid(pid)`, `is_kaanal_image`, `own_stem`, `COMM_LIMIT`  | Whether `pid` is a kaanal process, by image name: Windows `tasklist /FI "PID eq N" /FO CSV /NH`, unix `ps -p N -o comm=`. Accepted: `kaanal` (`kaanal.exe`) or the stem of the running executable (`current_exe`), case-insensitive. On Linux `comm` is cut to 15 characters, so a longer own stem is compared truncated to 15. Only `IsKaanal` allows a kill; `Other(name)` and `Unknown(why)` (the tool failed or showed nothing) never do.                                                                                    |
| `parse_tasklist_csv`, `parse_ps_comm`                                       | The two output parsers (first quoted field of the CSV line; last path component of the `ps` line). Pure, so tested on strings.                                                                                                                                                                                                                                                                                                                                                                                                   |
| `os_tool(name)`, `run_tool(name, args)`, `os_command(path)`                 | OS tools by full path: `%SystemRoot%\System32\NAME.exe` on Windows, the first of `/bin/NAME` and `/usr/bin/NAME` that exists on unix (a program placed earlier on `PATH` is never run; a system with neither, such as NixOS, cannot verify a pid, so `down` refuses to kill). `os_command` adds `CREATE_NO_WINDOW` on Windows: the daemon has no console, and a console program started from it would otherwise make Windows build one (measured at about 15 s).                                                                 |
| `kill_pid(pid)`                                                             | `taskkill /PID N /F` or `kill -KILL N`. Called only after `verify_pid` said `IsKaanal`.                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `force_stop(dir, token, pid, me, verify, kill)`, `Forced`, `still_ours`     | `down`'s force path. Refuses `pid == me`. `still_ours` (lock held, same token and pid in `run.json`; lock free or file gone means the instance left, a different token or pid is exit 1 `kaanal instance changed while stopping; not killing`) runs right before `verify` and again right before `kill`. An instance that exits meanwhile is `Forced::Stopped`, not a failure. After a kill it waits up to 2 s for the lock, then tidies with `clear_stale`. `verify` and `kill` are parameters so tests can simulate each race. |
| `stop_signal()`                                                             | Registers the stop handlers **now** and returns the future that waits for the first one: unix SIGTERM or SIGINT, Windows Ctrl+C, Ctrl+Break, console close, system shutdown (`recv_win!`, `recv_unix`). Called before anything is published, so an early signal is queued instead of killing the process undrained. A signal that cannot be registered never fires. `up` drains for 5 s on it; a second Ctrl+C during that is swallowed on unix and terminates the process on Windows.                                           |
| `ignore_hangup()`                                                           | Unix, for `--detached`: swallows SIGHUP like `nohup`. No-op on Windows.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `rotate_log(dir)`                                                           | Renames `kaanal.log` to `kaanal.log.1` (replacing it) and creates a fresh `kaanal.log` (0600 on unix). If the rename fails for any reason but "not found", it warns and truncates instead of refusing to start.                                                                                                                                                                                                                                                                                                                  |
| `spawn_detached(exe, args, log, cwd)`                                       | Starts the background process: stdin null, stdout and stderr the log, own process group on unix (`process_group(0)`; no `setsid`, which would need `unsafe`). On Windows `DETACHED_PROCESS \| CREATE_NEW_PROCESS_GROUP \| CREATE_NO_WINDOW`, first with `CREATE_BREAKAWAY_FROM_JOB`, retried without it on access denied (a job that forbids breakaway), all inside `kaanal_winhandle::without_inheritable_stdio` ([../kaanal-winhandle/lib.md](../kaanal-winhandle/lib.md)).                                                    |
| `Step`, `ReadyError`, `poll_until(budget, poll, step)`                      | The polling loop, separated from the process so it is tested with a fake step.                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `healthy(addr)`                                                             | `GET /__kaanal/health` is 200 (no proxy, no redirects, 2 s timeout, `Host: localhost:PORT`).                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `wait_ready(dir, child, budget, poll)`                                      | Ready means: the child has not exited, `run.json` carries **its pid** (never another instance's), the lock is held, and `healthy` answers.                                                                                                                                                                                                                                                                                                                                                                                       |
| `settle_unready(healthy, own_run, shutdown, wait_stopped, kill)`, `Settled` | A child that missed the deadline. Healthy now: `Settled::Healthy`, left alone (the note in `up_detached`). Else if `run.json` is its own, ask it to shut down and wait for the lock; then **always** `kill()` (the child handle is ours, killing a gone process is a harmless error), so a slow exit never hangs the caller. The steps are parameters for tests.                                                                                                                                                                 |
| `run_of(dir, pid)`                                                          | `run.json` if it is `pid`'s own.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `tail_log(path, n)`                                                         | The last `n` lines of the log, each through `clean` (the log holds server text). Reads the whole file; it is fresh per `up -d`, so small on a failed start.                                                                                                                                                                                                                                                                                                                                                                      |
