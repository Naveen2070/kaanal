# `crates/kaanal/src/commands/demo/mod.rs` and `commands/demo/files.rs` (private)

`kaanal demo`: the embedded e-commerce project, written to `.kaanal/demo/` and run through the same code as `up` (M1-F spec C1, C3, C4, C10, C12, C13). User page: [demo guide](https://kaanal.naveenr.in/docs/start/tour/).

## Flow

The template's `demo/kaanal.yaml` ends with a `traffic:` section, one profile `peak` (100 rps, 30 s, a journey per `endpoints:` key, GET 3 and others 1; RULES 58). Studio's starter (`GET /__kaanal/demo`) is the separate `kaanal-server/demo/studio.yaml`, which already had its own `peak`.

`demo` with `--eject` goes to `eject` first (no instance probe, no `.kaanal/`, no lock). Otherwise it checks without writing anything: `lifecycle::lock_probe` on `.kaanal/` (a running instance, any config, is usage 64 naming its port) and `check_locale` (usage 64 listing the tags). Only then `private_dir(".kaanal")`, `lock_instance` (lost a race since the probe: the usual "already running", exit 1), `write_template(".kaanal/demo", locale)`, a stderr note when `./kaanal.yaml` exists, `load`, and `serve_locked` bound to `127.0.0.1` with `--port` (default: the template's 8080 and `serve`'s +20 search). `.kaanal/` stays the state dir, so `down`, `chaos`, `logs` and `scenario` in the same folder find it through `run.json`.

## Items

| Item             | What it does                                                                                                                                                                                                                                                                                                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FILES`          | In `commands/demo/files.rs`: `(relative path, include_str! contents)` for every template file. Kept alone in its file because `tests/demo/main.rs` includes it with `#[path]`.                                                                                                                                                                                                      |
| `DemoArgs`       | `--port`, `--locale TAG`, `--open`; `--eject [DIR]` (conflicts with `--port` and `--open`, so those are clap usage errors, 64) and `--force` (requires `--eject`).                                                                                                                                                                                                                  |
| `write_template` | Writes every `FILES` entry under a folder (creating folders), replacing the template's `locale: en-IN` with the chosen tag. Other files there are left alone. Shared with `--eject`.                                                                                                                                                                                                |
| `check_locale`   | `kaanal_data::DataSet::load(".kaanal/demo")`: the built-in packs plus any in that folder's `locales/`. An exact tag match only, so `../x` and `en-us` are refused before anything is written.                                                                                                                                                                                       |
| `eject`          | `--eject`: `check_locale` against DIR (usage 64, nothing created), `refuse_link(DIR)`, a non-empty existing DIR is a usage error (exit 64) unless `--force`, then `write_template` (which overwrites only the template's files). Prints the absolute root and `cd DIR && kaanal up` (DIR quoted when it holds whitespace); `--json`: `root`, `written` (the `FILES` paths), `next`. |
| `demo`           | The flow above.                                                                                                                                                                                                                                                                                                                                                                     |
| `announce`       | The `serve_locked` callback. Text: `Demo:  http://localhost:PORT/#token=TOKEN`, `Seed:` with the locale, the login, one `kaanal scenario activate slow-db --ttl 30s` line, `Stop:`. `--json`: one object (`url` without the fragment, `host`, `port`, `pid`, `locale`, `seed`, `auth`, `warnings`), never the token.                                                                |
| `open_browser`   | `--open`: `rundll32 url.dll,FileProtocolHandler URL` (Windows), `open URL` (macOS), else `xdg-open URL`, each with the URL as one argument (no shell). Reaped on a side thread; a failure to start is a stderr warning, the demo keeps running.                                                                                                                                     |

Under `--json` the `Generating signing key...` line of `keys::signing_key` goes to stderr, so stdout holds only the object.
