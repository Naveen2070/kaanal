# `crates/kaanal/src/commands/down.rs`

`kaanal down`: stop a local instance (drain, then force) or ask a remote one to shut down. Split out of `main.rs` (R3.8); the overview of the commands is in [main.md](main.md).

## Functions

| Function                       | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `down(timeout)`                | `kaanal down`. `clear_stale` (lock free: print its line, exit 0) → `run_or_gone` (waits up to 5 s for `run.json`) → `post_shutdown` with the budget → if the answer is 202 or none (refused, or cut by a tiny budget), `wait_lock_free(timeout + 2 s)` and print `stopped`; any other answer (401, 5xx) skips the wait → no pid: exit 1 (or `stopped` if the lock just freed) → `lifecycle::force_stop` with `verify_pid` and `kill_pid` → `stopped` or `stopped (killed pid N after BUDGET)`. A second `down` during a longer drain cannot post (the listener is closed), so it waits its own budget + 2 s and then kills.                                                                                      |
| `down_remote(target, timeout)` | `kaanal --endpoint URL down` (E6): `POST /__kaanal/shutdown` with the budget (any answer but 202 goes through `Target::refused` or `HTTP N`), then `GET /__kaanal/health` every 100 ms for budget + 2 s. Gone means a refused, reset or aborted connection, or `Timeout::Connect` (Windows reports a closed port that way); any other answer, even a slow one, means still up. Prints `stopped` (exit 0), or exit 1 `still answering after Ns; not killing a remote instance`. Never reads a pid, `run.json` or the lock and never kills. On a firewalled or black-holed connection after an accepted shutdown the connect timeout can print `stopped` falsely: documented, `stopped` means "stopped answering". |
| `warn_all(v)`                  | Prints a response's `warnings` array to stderr as `warning: ...` (after `clean`); used by `scenario load` and `chaos set`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
