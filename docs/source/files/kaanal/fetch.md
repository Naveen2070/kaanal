# `crates/kaanal/src/fetch.rs` (private)

`kaanal init URL`: downloads an OpenAPI spec under hard limits (M1-F spec C8, C9). `init.rs` calls it; nothing else does.

## Flow

`gather` calls `parse` as soon as it has the argument, so a bad URL is a usage error (64) before any question. After the questions, `resolve_spec` in `init.rs` picks the file name, refuses an existing file without `--force` (64, before any request), and calls `fetch_spec`. Every request goes through a fresh `ureq` agent with `max_redirects(0)`, `http_status_as_error(false)` and a global timeout set to the time left of one 10 s budget. A 3xx is followed here: the `Location` is resolved against the current URL and must pass `check_hop`; a fourth redirect fails. A 2xx body is read through `take(cap + 1)`, so a missing or lying `Content-Length` cannot get past the cap, and must be UTF-8 that `kaanal_data::ApiModel::from_openapi` accepts. Every failure after `parse` is exit 1.

No cookies (ureq's `cookies` feature is off) and no `Authorization` (a URL with userinfo is refused). An `https` hop keeps ureq's default proxy, read from the environment (`HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY` and friends): nothing secret is sent. A plain `http` hop (always loopback, by `check_hop`) is built with `proxy(None)`, a deliberate deviation from "ureq's default": a proxy would fetch the proxy's own localhost (test `a_loopback_fetch_ignores_environment_proxies`).

`ureq` errors are never printed as text (they can quote the URL with its query, or server bytes): `failure` maps them to a category (timed out, DNS lookup failed, could not connect, TLS error, read error, bad response). Errors while reading the body unwrap the `ureq::Error` inside the `io::Error`, so a slow body is reported as a timeout.

## Items

| Item                         | What it does                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MAX_BODY`, `TIMEOUT`        | 10 MiB and 10 s, for the whole fetch including redirects.                                                                                                                                                                                                                                                                                                                          |
| `MAX_REDIRECTS`              | 3.                                                                                                                                                                                                                                                                                                                                                                                 |
| `is_url(arg)`                | The argument holds `://` (a Windows path never does). Such an argument is never treated as a path, so `ftp://...` is refused, not looked up as a file.                                                                                                                                                                                                                             |
| `shown(raw)`                 | The URL for messages: userinfo, query and fragment dropped (also for text that does not parse), control characters escaped. Every error names the URL this way and never quotes the response body.                                                                                                                                                                                 |
| `check_hop(from, to)`        | The policy for the first URL (`from` = `None`) and every redirect: no userinfo; `https`, or plain `http` only to `localhost`, `127.0.0.0/8` or `::1`, and never from `https` down to `http`; any other scheme is refused. Without the `https` feature an `https` URL is refused, naming the feature. Pure.                                                                         |
| `parse(arg)`                 | `url::Url::parse` plus `check_hop`; failures are usage errors (64).                                                                                                                                                                                                                                                                                                                |
| `file_name(url)`             | The last path segment, percent-decoded, reduced to `[A-Za-z0-9._-]` (anything else becomes `_`), when it starts with a letter or digit, ends in `.yaml`, `.yml` or `.json`, is at most `MAX_NAME` (100) characters and its stem is not a Windows device name (`con`, `prn`, `aux`, `nul`, `com1`-`com9`, `lpt1`-`lpt9`, any case); else `openapi.yaml`. Never `kaanal.yaml`. Pure. |
| `failure(e, timeout)`        | A `ureq` error as a short category, see above.                                                                                                                                                                                                                                                                                                                                     |
| `fetch_spec(url)`            | `fetch_with` at the real limits.                                                                                                                                                                                                                                                                                                                                                   |
| `fetch_with(url, cap, time)` | The loop described above; the parameters exist so the tests can use a small cap and a short timeout.                                                                                                                                                                                                                                                                               |

## The `https` feature

`crates/kaanal/Cargo.toml` has `default = ["https"]` and `https = ["ureq/rustls"]`: rustls with the `ring` provider and the `webpki-roots` certificate bundle (no platform verifier). `ring` compiles C code through `cc`, so a build needs a C compiler (on Windows, the MSVC build tools the Rust MSVC toolchain already needs). ureq 3.4 offers no pure-Rust provider: its other choice is `aws-lc-rs`, which needs more of a C toolchain (RULES R1.16). `--no-default-features` builds without TLS; `https://` is then a usage error. The control agent in `main.rs` is unchanged and only ever speaks plain HTTP to loopback.
