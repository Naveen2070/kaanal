# `kaanal/src/commands/sim/` (`mod.rs`, `print.rs`)

`kaanal sim run|sweep|list|show|report`, `kaanal sample` and `kaanal skeleton`: thin clients of the simulation routes (R2.6; `docs/web/simulation.md`, `docs/source/files/kaanal-server/sim.md`).

- **`sim run`.** `--profile NAME` or `--file FILE` (YAML or JSON, one profile; not both). With neither, it sends the empty name and the server says what the project has (`no traffic profile is defined: ...` or `name one with -p: ...`, RULES 58); the 404 is turned back into a usage error, exit 64, as before, with the server's text alone. `--duration` and `--warmup` are humantime strings sent as seconds (`bad --duration` is a usage error). It posts, then polls `GET /sim/runs/{id}` every 250 ms for up to five minutes (`--no-wait` prints the id and returns). A failed run prints its error and exits 1; a 409 while another run is going carries the server's "already in progress" message.
- **`sim sweep`.** The same profile handling, the same 404-to-usage turn and the same wait as `run` (`profile_of`, then `start`, which posts, waits and prints), on `POST /sim/sweep`. `--p99` goes through `secs` and is sent as `p99_ms` (zero is refused); `--errors` takes `1%` or `1` (an optional `%` stripped, 0 to 100) and is sent as `error_pct`; both are usage errors (64) before any request. `--max-factor` is passed through for the server to check (1 to 64). It never fetches `/log` (a sweep has none, `409`).
- **Sweep text.** `print_sweep`, from `sweep` of the record alone (not `sweep_points`): the verdict line (`knee at N req/s (Kx), the last point within the limit; the next point is over: p99 over 500ms`, the limit named from the first point that fails it, which is the point after the knee), the first node to saturate with its analytic `saturates_at_req_s`, the dominant cause, the warnings, the label, then one row per point (`load req/s`, `goodput`, `p99`, `errors`, `ok`). A cut ladder (`stopped_at`) prints nothing of its own: the sim's warning says where and why (hop caps or the rate cap), with the req/s. `sim show` picks it when `kind` is `sweep`.
- **Report text.** The label first, then requests, failures and p50/p95/p99/max, failures by kind, the five busiest nodes (load, utilization, mean wait, measured against expected visits per second, `SATURATED`) and the warnings. `--json` prints the record as one line.
- **`sim report ID [-o FILE] [--force]` and `sweep --report FILE`.** `report_text` fetches `GET /sim/runs/{id}/report` (`?format=json` under `--json`) through `call_text`, the text twin of `call` in `instance/remote.rs` (both go through one private `request`, so the target, token, timeouts and the `{error}` handling are shared); the text goes through `clean_lines` and ends in one newline. `-o` and `--report` write with `write_file` (the `create_new` writer `skeleton` uses, factored out): an existing file is refused without `--force`. `--report` conflicts with `--no-wait` (clap, exit 64) and, if the file exists, fails before the sweep is posted; it writes after `start` (which now returns the id) came back, so a failed sweep writes nothing, and says `wrote FILE` on stderr. `sim show` of a sweep adds `seed N` and `fingerprint X` lines when the record has them, and `chaos in force: ...` (`chaos_line`: `scenario NAME`, `none`, or `live chaos: [active scenarios a, b; ]N entries, digest X`, the report's words, then `(defined at runtime)` or `; defined at runtime: a, b` and `; chaos digest C` when the record has them).
- **`sample ROUTE`.** The positional is named `route` because `--endpoint` is a global flag. The body goes to stdout (pretty JSON), the size and status to stderr, so the body can be piped.
- **`skeleton`.** Prints the YAML; with `-o` the file is opened with `create_new`, so an existing file is refused without `--force` (no check-then-write race).

- **Layout.** `mod.rs` holds the commands (post, wait, fetch, write); `print.rs` holds `print_run`, `print_sweep` and their helpers (`pct`, `ms`, `share`, `print_cost`), read from the record alone, plus the `pct` unit test. Split from one 637-line file per AGENTS.md, code moved unchanged; `print_run` and `print_sweep` are `pub(super)`.
- **Report and file guards.** `report_text` fails with `the server sent no report text` for an empty body, so no command writes a blank file. `sim report --json -o` prints `{"written": FILE}` like `skeleton`. `write_file` with `--force` calls `replace_file`: a new temp sibling `FILE.PID.N.kaanal-tmp` made with `create_new` (`O_CREAT | O_EXCL`, so a file or symlink planted at that name is never opened, followed or clobbered; a clash takes the next `N`, 16 tries), written and synced, then renamed over `FILE`, so a failed write leaves the old file whole; on any failure the temp is removed. `NEXT` is a module-level counter so the tests can read it. Unit tests in `commands/sim/mod.rs` (they hold one test lock so none moves `NEXT` under another): a planted `FILE.kaanal-tmp` and the exact `FILE.PID.N.kaanal-tmp` names the next four attempts use stay as they were, and `NEXT` moved by five (four clashes retried); a symlink at those names is not written through (Unix); a failed rename (the target is a directory) leaves no temp.

Tests: `tests/cli/sim.rs`.
