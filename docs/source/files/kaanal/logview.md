# `crates/kaanal/src/util/logview/mod.rs`

Pure rendering and filtering for `kaanal logs` and `kaanal trace`: log lines, the ASCII waterfall, the follow de-dup set and printer loop, the client-side filter and the SSE line parser. No network (the commands in [main.md](main.md) do the fetching), so all of it is unit tested with golden strings. User reference: [observability guide](https://kaanal.naveenr.in/docs/guides/observe/observability/).

Every piece of text that came from the server (node names, paths, client ids, causes) goes through `clean` first, which replaces control characters with `?`. A node called `\x1b[31m` can neither recolor nor move the terminal.

## Rendering

| Item               | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `line(v)`          | One log line from a log entry **or** an SSE `request` event (they share these fields): `HH:MM:SS.mmmZ  id  METHOD path  status  Nms`, then `scope=`, `pinned=`, `failed=`, `kind=`, `client=` when they are strings, then the `rejected` word. UTC from the millisecond timestamp.                                                                                                                                                                  |
| `waterfall(entry)` | The trace view. Header: id, request, status, `served Nms` (measured) and `trace N.Nms` (simulated), then `scope=`, `pinned=`, `client=` and `flags=` when present. A row per hop: `node.what` (the `op` of an `op` hop, else the kind), start, duration, the bar, the note. A hop-less entry shows `- (unmatched)` or whatever `rejected` says, else `- (no hops recorded)`. Footer: `... more hops (truncated, N shown)`, then the ending (below). |
| `bar`, `col`       | The 40-column bar of one hop (`BAR`): `.` queue wait, then `#` (`x` for a cut hop or the failed hop) of **at least one column**, so a 0.1 ms hop is visible; columns are clamped so a hop at the very end fits. A zero total gives column 0.                                                                                                                                                                                                        |
| notes              | The hop's `why`, then `lane N` for a non-zero lane.                                                                                                                                                                                                                                                                                                                                                                                                 |
| ending             | With a `chain_error`: `failed at NODE: STATUS[ KIND] (CAUSE)` (the kind only when it is not a plain `status`), or, when a pin replaced the failure (`pin` set, no `failed_node`), `pinned=STATE hid: NODE.error=STATUS`. The failed hop is the **last** hop of that node, and it is drawn with `x`.                                                                                                                                                 |

## Follow (`logs -f`)

| Item                                      | What it does                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Sse`                                     | Assembles SSE lines (`event:`, `data:`, blank line) into `(event, data)` messages; comments and keep-alives are ignored.                                                                                                                                                                                                                                              |
| `lossy_line(bytes)`                       | One line from raw bytes: invalid UTF-8 becomes U+FFFD, the line break goes. Reading is by bytes so one bad byte does not end the reader.                                                                                                                                                                                                                              |
| `BACKLOG` (4096), `forward`               | The reader thread's queue to the printer is a bounded `sync_channel`. `forward` uses `try_send`: when the queue is full it **counts** the message in an `AtomicU64` instead of blocking the socket (a `request` counts one, a server `lagged` message counts what it reports). Memory is bounded; loss is visible.                                                    |
| `take_lagged`, `lagged_notice`            | The count so far (reset to 0) and the text `-- missed N requests (follow slower than the server) --`.                                                                                                                                                                                                                                                                 |
| `drain(rx, dropped, idle, out, on_event)` | The printer loop. Before each wait, after an idle wait of `idle` (so a quiet follower still reports) and at the end of the stream however it ended, it prints the notice if drops were counted. A `lagged` message prints its own notice; anything else goes to `on_event`. Returns `End::Marker` (the reader's end marker) or `End::Disconnected` (the reader died). |
| `Seen`, `SEEN_CAP` (2000)                 | The ids already printed. A request in both the tail and the stream is printed once; the set is bounded to the last 2000 (an older id may print again, which cannot happen in practice since the stream only carries new requests).                                                                                                                                    |
| `filter_of`, `passes`                     | The server's own `Filter::from_params` for the flags (so a bad value fails identically) and a predicate over a JSON entry **or event**. The event carries `endpoint`, so `--endpoint` filters live lines client-side. `since`, `scope`, `failed` and `status` use the fields every event has.                                                                         |
