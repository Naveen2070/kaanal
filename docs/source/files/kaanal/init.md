# `crates/kaanal/src/commands/init/mod.rs` (private)

`kaanal init SPEC`: a starter project from an OpenAPI file (RULES R1.20; M1-F spec C6 to C8, C15).

## Flow

`init` refuses an existing `kaanal.yaml` without `--force` (usage error 64), then `gather` collects and validates the answers (a URL spec is checked by `fetch::parse` first), then `resolve_spec` downloads a URL spec beside the config ([fetch.md](fetch.md)), then the spec must be a readable file, then `write_checked` writes `kaanal.yaml.tmp`, runs `load`, `kaanal_server::check` and `spec_routes` on it (an empty route list is an error), and renames it to `kaanal.yaml`. The temp file is removed on any failure, and so is a spec this run downloaded (`Saved::undo`; a forced download moves the old file back from its `.kaanal-old` backup). On success `Saved::keep` deletes the backup and the output names the replaced spec (`replaced` in `--json`). `.gitignore` is touched only after the rename.

## Items

| Item               | What it does                                                                                                                                                                                                                                                                                                                                                           |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `InitArgs`         | The clap arguments: `SPEC`, `--yes`, `--force`, `--service`, `--port`, `--locale`.                                                                                                                                                                                                                                                                                     |
| `Params`           | Validated answers handed to `render_config`.                                                                                                                                                                                                                                                                                                                           |
| `gather`           | Flag, else prompt (only when stdin is a terminal and not `--yes`), else default: `app`, 8080, `en-IN`. Questions go to the prompt stream (stderr). A bad flag is a usage error; a bad typed answer is explained and re-asked, three tries, then usage 64 (`field`). Validators: `parse_service` (name rule, not gateway/database/cache), `parse_port`, `parse_locale`. |
| `ask`              | `prompt [default]:`, one line; empty line or end of input gives the default. Generic over `BufRead`/`Write`.                                                                                                                                                                                                                                                           |
| `valid_name`       | Hand-checked `^[a-z][a-z0-9_-]{0,31}$`: the only text written into YAML unquoted.                                                                                                                                                                                                                                                                                      |
| `render_config`    | Pure. Schema header, `port`, `locale`, gateway (nginx), service (spec as a JSON-escaped string), database (postgres), cache (redis), three edges, no `endpoints:`.                                                                                                                                                                                                     |
| `resolve_spec`     | A path is used as given. A URL: name from `fetch::file_name`; an existing file there needs `--force` and a free `<name>.kaanal-old` (both 64, checked before fetching); `fetch::fetch_spec`; then the old file is renamed to the backup and the download written with `create_new`. Returns the path and a `Saved` record.                                             |
| `Saved`            | The downloaded file's name and the backup, if any. `undo` removes the download and renames the backup back; `keep` deletes the backup. A failing step is a stderr warning naming the file, never silent.                                                                                                                                                               |
| `ignore_state_dir` | Reads `.gitignore` only to find the line (`.kaanal`, `.kaanal/`, `/.kaanal`, `/.kaanal/`, `.kaanal/*`, `.kaanal/**`), then appends with `OpenOptions::append` in the file's own line ending. Unreadable or non-UTF-8 files are never touched: `Err(reason)`, which `init` prints as a stderr warning and carries on (exit 0).                                          |
| `write_checked`    | Creates `kaanal.yaml.tmp` with `create_new` (an existing one is a usage error and is left alone), `load` + `check` + non-empty routes, rename; our temp file is removed on any failure; an existing `kaanal.yaml.tmp` is refused and kept; errors say `kaanal.yaml`.                                                                                                   |

The config has no project-name field, so init does not ask for one.
