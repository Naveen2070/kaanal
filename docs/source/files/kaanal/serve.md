# `crates/kaanal/src/commands/serve.rs`

`kaanal up`: start the server in the foreground or detached, the startup banner and the exposure warnings. Split out of `main.rs` (R3.8); the overview of the commands is in [main.md](main.md).

## Functions

| Function                                                                        | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `up(config, port, host, detached)`                                              | `load`, `private_dir`, `lock_instance`, then `serve_locked` (below). Full lifecycle: `private_dir` → `lock_instance` → remove any stale `run.json` (the lock proves it is not a live instance's) → signing key (`keys::signing_key`, only when the config has an auth node; after the lock, before binding, so a bad key file stops startup by name) → warn on non-loopback host → token → tokio multi-thread runtime → `lifecycle::stop_signal()` (handlers registered first, and `ignore_hangup` when `detached`) → `serve` → `write_run_file` (with the token-free `startup` object) → `tokio::select!` on the server ending (a `POST /__kaanal/shutdown` ends `wait` by itself) versus the stop signal, which calls `server.stopper()(5 s)` and awaits the drain → remove `run.json` only if it still holds _our_ token (a newer instance may have replaced it). With `detached` the `UI:` line is printed without `#token=`. Under `determinism: realistic` it prints `Seed:  N (determinism: realistic; replay its timings and failures with determinism: controlled and seed: N; generated data then follows that seed too)` after the `UI:` line. |
| `serve_locked(config, loaded, port, host, detached, lock, announce)`, `Started` | Passes the config file and its text to `ServeOpts.draft` (the Studio draft starts as the file).  Everything in `up` after the instance lock, shared with `kaanal demo` (which takes the lock itself, after its own checks). `announce` gets a `Started` (port, token, `Auth:` text, drawn seed, seed in force, warnings) once `run.json` is written, and prints the start lines: `up` its `Mocks:`/`UI:`/`Auth:`/`Seed:` lines, `demo` its own.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `up_detached(config, port, host, wait)`                                         | `kaanal up -d`. `load` and `kaanal_server::check` (a bad config is a placed error, exit 1, nothing created) → `private_dir` if `.kaanal` is missing → `lock_start` → `clear_stale`: `None` (lock held) → `already_running`; else `private_dir`, `exposure_warning`, `rotate_log`, open the log for append, `spawn_detached` (the same executable: `up -c CONFIG --port PORT --host HOST --detached`, port and host already resolved, same working directory) → `wait_ready`. Ready: `print_started`, then `Log: <absolute path>` and `Stop: kaanal down`, exit 0. The child exited: if the lock is held a simultaneous `up -d` won, so `already_running`; else exit 1. Timed out: `settle_unready` (healthy: `note: kaanal answered just after the Ns wait; leaving it running` on stderr and exit 0; else shut down, wait, kill) then exit 1 `no answer within Ns`. Every failure ends `kaanal did not start: WHY; last lines of LOG:` and `tail_log(20)` (or `(log is empty)`).                                                                                                                                                                         |
| `lock_start(state)`                                                             | Blocking exclusive lock on `.kaanal/start.lock`, held by the parent until it returns (not inherited by the child). Two simultaneous `up -d` run one after the other, so the loser finds the instance running and does not rotate the live log away. The wait is bounded by the winner's `--wait` plus its checks, not by the loser's own `--wait`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `print_started(run)`, `already_running(state)`                                  | The `Mocks:`, `UI:` (with the token), `Auth:` and `Seed:` lines rebuilt from `run.json`'s `startup`, warnings on stderr; `already_running` adds `already running (pid N)` and exits 0 (it waits up to 5 s for `run.json`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `exposure_text(host)`, `exposure_warning(host)`                                 | The non-loopback `--host` warning, printed by `up` and also by the `up -d` parent (the child's copy goes to the log).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `seed_line(seed)`                                                               | The `Seed:` line, shared by `up` and `print_started`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `start_budget(s)`, `drain_budget(s)`                                            | clap value parsers for `--wait` (1 ms to 1 h) and `--timeout` (1 ms to 300 s, the range the server accepts): `humantime`; a bad value is a clap error and so exit 64.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

## Self-check after binding (D2)

`serve_locked` starts `kaanal_server::selfcheck` on a plain detached thread right after the server is bound, so a big spec never delays startup; its warning lines (generated samples that break the response schema) are printed to stderr when it finishes. A plain thread, not a blocking task, so shutdown never waits for it.
