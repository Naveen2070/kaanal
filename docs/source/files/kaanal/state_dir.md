# `crates/kaanal/src/instance/state_dir.rs`

The `.kaanal/` state directory: a private folder, the one-instance lock and `run.json`. Split out of `main.rs` (R3.8); the overview of the commands is in [main.md](main.md).

## Functions

| Function                                       | What it does                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `private_dir(dir)`                             | Creates `dir` (and missing parents) private **before** any secret is written (rule R5.8); used for `.kaanal` and, on every `up` with an auth node, for the signing-key directory (`keys`): Unix 0700; Windows ACL replaced with a single grant for the current user. Failure on Windows warns and continues — the token still protects the API.                       |
| `restrict_to_current_user(dir)`                | Windows ACL via `whoami.exe` (SID lookup) and `icacls.exe` (inheritance removed, one full-control grant, then explicit grants to Everyone, Users and Authenticated Users removed on the folder and its files; not `/reset`, which would briefly widen a running instance's files), both invoked by **full System32 path** so a planted earlier-PATH exe is never run. |
| `lock_instance()`, `lock_at(path, tries, gap)` | Exclusive `File::try_lock` on `.kaanal/lock`, held for the process's life (rule R6.7). `WouldBlock` is retried 10 times, 20 ms apart (a status probe holds a shared lock for an instant), then "already running" with the port if known: a true "already running" costs about 200 ms. The OS releases the lock even on a crash, so there is no stale-lock cleanup.    |
| `write_run_file(bound, token, startup)`        | Writes `{host, port, token, pid, startup}` (`startup` is `{auth, seed, warnings}`, no token, so a second `up -d` can print the lines) via temp file + rename; `host` is the bound address, or loopback when bound to all interfaces. Temp file + rename (a concurrent `status` never reads half a file); 0600 on Unix.                                                |
