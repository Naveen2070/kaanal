# `crates/kaanal-server/src/control/{studio,assets,manifest}.rs` and `crates/kaanal-server/build.rs`

Serves Studio's built bundle (the page and its hashed, code-split files), or the status page when there is none. User page: [studio guide](https://kaanal.naveenr.in/docs/guides/simulate/studio/).

## What it does

`build.rs` reads `ui-dist/.vite/manifest.json` (written by the UI build). It embeds **exactly the files the manifest references** under `assets/` (never a directory walk), with their `.br` and `.gz` siblings when present, into a generated table (`OUT_DIR/studio_bundle.rs`), and sets `cfg(kaanal_ui)` (declared with `cargo::rustc-check-cfg`). With no manifest it prints a `cargo:warning` and Studio is the status page. It never runs Node, npm or `vp`, and re-runs when `ui-dist` or a referenced file changes. A referenced file that is missing, a name outside `[A-Za-z0-9._-]`, or a reference with a `.`/`..` segment under an allowed extension **fails the build**.

`manifest.rs` holds the parsing and the code generation, shared with `build.rs` through `#[path]` so the same code is unit-tested. Extensions allowed: `js css woff2 svg png`. `index.html`, dot files, `.map` files and the manifest are never in the table. A file is `immutable` only when it has at least one vote and every vote says hashed: a chunk's own output name must be its source name (or the entry's `name`) then `-` and a non-empty hash; files listed only under `css[]`/`assets[]` do not vote.

## Items

| Item                                       | Kind     | What it does                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------ | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `studio(State)`                            | async fn | `GET /__kaanal/studio`. With a bundle: the embedded `index.html` with a page CSP (`script-src 'self'`, `style-src 'self' 'unsafe-inline'`, `font-src 'self'`, `connect-src 'self'`, `frame-ancestors 'none'`) and `Referrer-Policy: no-referrer`. Without: `admin::ui`, the status page.                                                                                                        |
| `studio_asset(..)`                         | async fn | The route `/__kaanal/studio/{*rest}`, any method. Serves only an exact table hit on `GET`/`HEAD` with no query; everything else is 404 (the guard answers 401 first without a token). Sets `Content-Type`, `Cache-Control` (`immutable` or `no-cache`), `Vary: Accept-Encoding`, a per-encoding `ETag` and 304 on a matching `If-None-Match`; SVG also gets its own restrictive CSP. No ranges. |
| `Asset`, `Encoding`, `Bundle`              | types    | One embedded file (name, type, identity/br/gz bytes, hash, immutable); the encoding picked; the table the server reads (injectable, so tests use a fixture table).                                                                                                                                                                                                                              |
| `lookup(table, name)`                      | fn       | Exact-match lookup.                                                                                                                                                                                                                                                                                                                                                                             |
| `hit(bundle, method, uri)`                 | fn       | **The one test of "this request is an asset hit"** (GET/HEAD, no query, the raw undecoded path equals the prefix plus a table name), called by both the guard and the handler so they cannot disagree.                                                                                                                                                                                          |
| `negotiate(accept_encoding, asset)`        | fn       | `br`, then `gzip`, then identity; honours `q=0` and `*`; a malformed header is identity.                                                                                                                                                                                                                                                                                                        |
| `etag_for(asset, enc)`, `etag_matches(..)` | fns      | Strong quoted ETag per encoding; `If-None-Match` lists, `*` and weak compare.                                                                                                                                                                                                                                                                                                                   |
| `cache_control(asset)`                     | fn       | `public, max-age=31536000, immutable` or `no-cache`, keyed by file.                                                                                                                                                                                                                                                                                                                             |

The guard in [guard.rs](control.md) exempts `health`, `ui`, `studio` and `assets::hit` (R1.106, amending R5.2); its other headers still apply and it keeps a handler-set `Cache-Control` (`mark_response`). `AppState.studio` holds the bundle (`serve_with_studio` takes another for tests). Tests: `tests/studio_assets/`, and unit tests in `assets.rs` and `manifest.rs`.
