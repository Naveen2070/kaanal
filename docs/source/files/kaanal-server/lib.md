# `crates/kaanal-server/src/lib.rs`

Server entry: binds the port, builds state, installs the router.

## What it does

The only public surface the binary uses. One axum router serves **both** the control API and the mocks on one port (spec FR-API-12). Control routes are mounted first and wrapped in the `guard` middleware via `route_layer`, so the mock fallback can never accidentally bypass authentication. Declares the private `scenarios` module (file discovery and atomic save, [scenarios.md](scenarios.md)) and the private `scope` module (`X-Kaanal-Scenario` scoping, [scope.md](scope.md)). Declares the request-log modules `log` ([log.md](log.md)), `record` ([record.md](record.md)) and `log_api` ([log_api.md](log_api.md)); `log`'s public types (`LogEntry`, `HopRec`, `ChainErrorRec`, `LogRing`, `Page`, `Lookup`, `Filter`, `StatusMatch`, `IdGen`, `LOG_CAP`, `MAX_HOPS`, `MAX_TRACE`, `format_id`, `parse_id`, `client_id`, `matches`) are re-exported because the CLI parses the same filter grammar for `logs -f`. Declares the private `shutdown` module (the graceful stop, [shutdown.md](shutdown.md)). `serve` also spawns `control::lease_task`, which expires `ttl` leases and stops when a shutdown is requested. Mock requests run through one replay-engine actor task, so queues, pools and rate limits are shared by every request.

## Items

| Item                                                                        | Kind   | What it does                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ServeOpts`                                                                 | struct | `host`, `port` (0 = OS-chosen, used by tests), `token`, `auth_key` (the signing key `kaanal up` loads; required when the config has an auth node, else `serve` fails closed), `draft` (`Option<DraftSource>`: the config file and its text, to start the Studio draft from; `None` starts it empty).                                                                                             |
| `BoundServer`                                                               | struct | `addr` (actual bound address), `warnings` (non-fatal load findings), `drawn_seed` (the chain seed drawn at startup under `determinism: realistic`, else `None`; print it so the run can be replayed as `controlled`), private `handle` (the spawned serve task) and `shutdown` (the same `Shutdown` as `AppState.shutdown`).                                                                     |
| `BoundServer::wait()`                                                       | fn     | Awaits the serve task, or the deadline of a shutdown request (`Shutdown::expired`): then it aborts the serve task and returns `Ok`. Returns the IO error that stopped the server otherwise. The connections themselves are cut by the `Cut` listener, not by the abort.                                                                                                                          |
| `BoundServer::shutdown(budget)`, `BoundServer::stopper()`                   | fn     | Starts the same graceful stop as `POST /__kaanal/shutdown` and returns the time left (the first call fixes the deadline, later ones never extend it). `stopper()` returns it as an owned `Fn(Duration)`, for a caller that has already handed `self` to `wait()` (which consumes it): `up` calls it from the signal branch.                                                                      |
| `spec_routes(cfg, base_dir) -> Result<(Topology, Vec<RouteSpec>), Located>` | fn     | The topology and the routes every spec defines (key, owner, inferred op), read exactly as `AppState::build` reads them. Backs `kaanal endpoints`; errors are placed in `kaanal.yaml`.                                                                                                                                                                                                            |
| `check(cfg, base_dir) -> Result<Vec<String>, Located>`                      | fn     | Full dry-run: builds `AppState` (config, topology, spec files, endpoints inline or from the endpoints file, route conflicts) without binding a port. Backs `kaanal validate`. Returns warnings on success; errors carry their place in `kaanal.yaml` or in the endpoints file (`Located::in_source`, `Located.file`).                                                                            |
| `selfcheck(cfg, base_dir) -> Result<Vec<String>, Located>`                  | fn     | Samples each spec endpoint with its node's own `Options` and validates the bodies against the response schema ([kaanal-data selfcheck](../kaanal-data/selfcheck.md)); one warning line per endpoint, prefixed with the spec file. `validate` runs it inline; `up` runs it after binding.                                                                                                         |
| `new_token() -> String`                                                     | fn     | 32 random bytes as 64 hex chars. New on every `kaanal up`.                                                                                                                                                                                                                                                                                                                                       |
| `serve(cfg, base_dir, opts) -> Result<BoundServer, Located>`                | fn     | Binds the listener, builds `AppState`, builds the auth `Issuer` (an auth node without `opts.auth_key` is an error: fail closed), spawns the replay-engine actor ([actor.md](actor.md)) into `AppState.engine`, spawns `axum::serve` on the tokio runtime over the `shutdown::Cut` listener with `with_graceful_shutdown(requested())`, returns the handle. `AuthKey` is re-exported (`pub use`). |
| `bind(host, port)`                                                          | fn     | Tries the requested port, then the next 20, before giving up with a message listing the range.                                                                                                                                                                                                                                                                                                   |

## Route table

| Route                                                        | Handler                                                      | Notes                                                                                       |
| ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| `GET /__kaanal/health`                                       | inline                                                       | `{ "ok": true }`; no token needed (liveness probe)                                          |
| `GET /__kaanal/topology`                                     | `control::topology`                                          | nodes, edges, route keys                                                                    |
| `GET/PUT/DELETE /__kaanal/chaos`                             | `control::get_chaos` / `set_chaos_keyed` / `clear_keyed`     | nested list / keyed set (node, endpoint or both) / clear a key or, with no query, all chaos |
| `PUT/DELETE /__kaanal/chaos/{node}`                          | `control::set_chaos` / `clear_node`                          | merge a patch / clear one node                                                              |
| `GET/DELETE /__kaanal/scenarios`                             | `control::list_scenarios` / `clear_scenarios`                | defined scenarios / deactivate all (live stays)                                             |
| `GET/PUT/DELETE /__kaanal/pins`                              | `pin_api::get_pins` / `put_pin` / `delete_pins`              |                                                                                             |
| `POST /__kaanal/cycle`                                       | `pin_api::cycle`                                             |                                                                                             |
| `GET/PUT/DELETE /__kaanal/payload`                           | `control::list_payloads` / `put_payload` / `delete_payload`  | live response edits ([payload.md](payload.md))                                              |
| `GET /__kaanal/payload/preview`                              | `control::payload_preview`                                   | what the route answers with no edit                                                         |
| `GET/PUT /__kaanal/scenarios/active`                         | `control::get_active` / `set_active`                         | the stack and the compiled result / set the whole stack atomically                          |
| `POST /__kaanal/scenarios/save`                              | `control::save_scenario`                                     | write `scenarios/NAME.yaml`                                                                 |
| `GET/PUT/DELETE /__kaanal/scenarios/{name}`                  | `control::get_scenario` / `put_scenario` / `delete_scenario` | one definition / define at runtime / undefine a runtime scenario                            |
| `POST /__kaanal/scenarios/{name}/activate`, `.../deactivate` | `control::activate` / `deactivate`                           | push to the top (optional `{"ttl"}` lease) / remove from the stack                          |
| `POST /__kaanal/reset`                                       | `control::reset`                                             | clean slate for `beforeEach`                                                                |
| `GET /__kaanal/logs`                                         | `log_api::logs`                                              | the request log, filtered ([log_api.md](log_api.md))                                        |
| `GET /__kaanal/trace/{id}`                                   | `log_api::trace`                                             | one entry by id, `last` or client id                                                        |
| `GET /__kaanal/events`                                       | `control::events`                                            | SSE stream: `request` and `scenario` events (incl. `expire`); ends with a `shutdown` event  |
| `POST /__kaanal/shutdown`                                    | `control::shutdown`                                          | graceful stop with a drain budget                                                           |
| `GET /__kaanal/ui`                                           | `control::ui`                                                | embedded HTML page; no token needed (page reads it from the URL fragment)                   |
| _(fallback)_                                                 | `mock::handle`                                               | every other path → mock engine                                                              |

The static segments `active` and `save` win over the `{name}` capture (matchit prefers static segments; both are also reserved scenario names). The `route_layer(guard)` covers exactly the routes above it in the builder — a new control route added there cannot forget authentication.

`serve_blank(base_dir, file, opts)` starts with no system (see [draft](draft.md)): the control API and the UI work, the mock answers 404 `no system applied yet`, the draft is `BLANK_TEXT` to be saved at `file`, and the first Apply makes generation 1. `opts.draft` is ignored. `serve` and `serve_blank` share `open` (bind the port) and `launch` (share the state, start the lease task and the server). `BLANK_TEXT` is re-exported.
