# `crates/kaanal-server/src/collections.rs`

The `collection:` routes: small in-memory lists of JSON objects (F, spec section 5). User page: [../../../web/collections.md](../../../web/collections.md).

## What it does

`AppState.collections` holds one `Collections` per running server, shared by every scope and every user (C14). [mock](mock.md) `read_body` builds a `Call` before the chain (for an add, the body is read then, capped); `answer` applies it, and only when the reply is the route's normal one: a chain `Ok`, or a `loading`, `slow` or `success` pin. A wire failure at a wire node shows `Call::preview` instead (and when that preview has no body to cut, a 204 or a `HEAD`, `chaos_reply` answers as at a non-wire node: the kind's default status and chaos body, never a clean success); a chaos failure, a pinned `error` or a pinned `empty` drops the `Call` unused. `Call::apply` takes `self`, so a request can change its collection at most once. `POST /__kaanal/reset` calls `clear`.

## Items

| Item                                     | Kind        | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `MAX_ITEMS`, `MAX_ITEM_BYTES`            | const       | 1000 items per collection; about 64 KiB per item (serialized before its `id`, checked before the lock). Not configurable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `Collections`                            | struct      | One `Mutex<HashMap<name, List>>`; a `List` (private) is the items in insertion order and the last id handed out. The lock is never held across an `.await`; a poisoned lock is used as is.                                                                                                                                                                                                                                                                                                                                                                                                       |
| `Collections::apply(name, op, id, item)` | fn          | `List`: 200 and every item. `Get`: 200 or 404 `{"error":"not found"}`. `Add`: 400 `{"error":"item must be a JSON object"}` (missing or not an object), 413 `{"error":"item too large"}`, 409 `{"error":"collection full"}`, else 201 and the item with `id` (a client `id` is overwritten). `Remove`: 204 `null` or 404. An id that is not a canonical `u64` (`007`, `+7`, `-7`) names no item. Items come back with sorted keys (serde_json without `preserve_order`). A list clones the collection under the lock (about 64 MB at most). Ids count from 1 per collection and are never reused. |
| `Collections::clear()`                   | fn          | Empties every collection; ids start at 1 again.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `run(.., commit)` (private)              | fn          | `apply` with `commit: true`; with `false` it answers the same and changes nothing (the preview).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `op_of(route)`                           | fn          | The route's `CollectionOp`, `None` without `collection:`. A synthesized `HEAD` uses its `GET` shape, so it reads and never writes.                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `read_item(req)`, `Item`                 | async fn    | Reads an add's body with `to_bytes(.., MAX_ITEM_BYTES + 1)`: over the limit (or a broken body stream) is a 413, anything serde rejects (invalid UTF-8, past its recursion limit) a 400. The error is answered only if the chain succeeds.                                                                                                                                                                                                                                                                                                                                                        |
| `Call`, `Call::apply`, `Call::preview`   | struct, fns | One request's operation (name, op, id, pending item). `apply(self)` answers a deferred body error or runs the op; `preview(&self)` does the same without changing anything.                                                                                                                                                                                                                                                                                                                                                                                                                      |
