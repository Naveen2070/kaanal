# `crates/kaanal-server/src/state.rs`

`AppState`: everything the running server knows, built once at startup.

## What it does

The load pipeline moved to [generation.md](generation.md) (`Generation::build`, shared by `serve` and `check`/`kaanal validate`); `AppState::build` calls it and installs the result. It runs: topology → OpenAPI specs → endpoints (inline map or the endpoints file) compiled by `kaanal_core::chain::compile` → scenarios (inline and `scenarios/*.yaml`) → route table. Every problem is a fatal `Located` error (a path into `kaanal.yaml`, or a place in the endpoints file, plus a precise message) or, for ignorable schema keywords, a collected warning.

## Seeds

`seed` is the config's `seed:`: generated bodies always use it, in both determinism modes (D14). `chain_seed` seeds the chain draws: `seed:` under `determinism: controlled`, a value drawn from OS entropy once at startup under `realistic` (the server draws it, so `kaanal-core` stays free of entropy). `drawn_seed` is `Some(that value)` under `realistic` and `None` otherwise; `up` prints it so the run can be replayed as `controlled`.

## Load pipeline (now `Generation::build`)

1. **Topology** — `Topology::build(cfg)`; any `TopologyError` aborts. (`concurrency`, pools and rate limits no longer warn: live mode enforces them through the engine actor.)
2. **Specs** (`load_specs`, via `read_api`, which `selfcheck` also uses) — for each service or monolith node with `spec`, reads the file (relative to the config's directory) and parses `ApiModel::from_openapi`. Warnings (ignored keywords) are collected, prefixed with the file name. Each endpoint becomes a `RouteSpec` plus its success status and schema, and, when `PageSpec::detect` finds a paging contract, its `PageSpec` (`Specs.paging`, by key). Two services defining the same `method + path` → error naming both owners (so `compile` always gets unique keys). `check_shape` runs on every path.
3. **Compile** (`compile_endpoints`) — `compile(topo, route specs, entries)`. Entries come from the inline `endpoints:` map, or from the file it names (relative to the config's directory), read and parsed here (`parse_endpoints`). Compile warnings (stale entries, ignored `via` error maps) join `warnings`.
4. **Scenarios** (`load_scenarios`, after compile because endpoints exist only then; it gets the load-time `empty_ok` built from the spec table by `pins::empty_ok`, so a scenario's `empty` pin is checked against the same rule the request uses) — each inline `scenarios:` entry is checked with `valid_name` and `resolve_scenario` (nodes and endpoints exist, an endpoint has an entry node, limits, duplicate keys; errors placed at `scenarios.<name>.chaos[i].<field>` in `kaanal.yaml`), then every `scenarios/*.yaml` found by `scenarios::discover` ([scenarios.md](scenarios.md)) is resolved the same way (errors placed in the file). Inline first, then files in name order; a name defined in both is a load error naming both sources. Warnings (an orphan kind/status, a pair the chain never visits, skipped files) join `warnings`, so `validate` and `up` show them. The scenarios directory is the config directory's canonical path plus `scenarios`, canonicalized once here (S16). The chaos state starts empty: scenarios are loaded, none is active.
5. **Routes** — one `Route` per compiled endpoint, in key order. A static endpoint (no owner) has its path shape-checked against the spec paths, so `/users/{uid}` next to a spec `/users/{id}` and the `/__kaanal` prefix are still rejected. A `HEAD` without a spec entry of its own takes GET's status and schema (R6.8). HEAD copies are served but not listed in `route_keys`. An `endpoints:` entry with `total:` on a route that is not paged gets a warning (it has no effect).
6. **Router** — paths go into `matchit::Router` in `BTreeMap` order, so a conflict always names the same path deterministically.
7. **Seed** — `cfg.seed_source()`: `Fixed` → no draw; `Entropy` → one `rand::random::<u64>()`.

## Error places

`build` returns `Located`: a scenario error is placed at `scenarios.<name>...` for an inline scenario and carries `Located.file` for a scenario file (a bad stem, size, UTF-8, name clash or parse error); topology errors use `TopologyError::located`; spec file and route-conflict errors use `nodes.<n>.spec`; a missing endpoints file is placed at the `endpoints:` value of `kaanal.yaml`; a parse or compile error inside the endpoints file carries that file (`Located.file`, plus `pos` for a parse error), so `kaanal` prints `kaanal.endpoints.yaml:line:col: ...`; a compile error from an inline entry uses `endpoints.<key>...`; a static route's shape error is placed at its entry; the router insert has an empty path (no position). A spec node with no edge from the gateway is rejected by the topology check before `compile` could meet it (a spec route without an entry has no place of its own).

## `check_shape`

Rejects two paths that differ only in parameter names (`/users/{id}` vs `/users/{uid}`) — matchit would fail with an unhelpful message, so this produces a clear one naming both spellings. Also reserves the `/__kaanal` namespace: a mock there would be served without CORS next to the control API (rule R5.4). `compile` checks neither, so the server runs it on every spec path and every static endpoint.

## Tests

[../tests.md](../../tests.md#crateskaanal-servertestsstaters) — conflict detection, endpoints file errors, warnings plumbing.

`AppState::blank(base_dir, token, port)` is a state with no generation (a blank start). `build` and `blank` share one private constructor (`assemble`). The startup seed is drawn at once (`drawn_seed` outlives every generation, so a realistic config applied later must find one), though the banner prints none.
