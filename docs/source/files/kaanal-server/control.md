# `crates/kaanal-server/src/control.rs`

The control API handlers and the security guard that stands in front of them.

## The guard (runs before every `/__kaanal/*` route)

`guard(State, req, next)` — a middleware, so it runs **before any extractor parses a body or query**; unauthenticated callers never reach handler code:

1. **Host check** — `host_allowed(host, port)`: must be `localhost`, `127.0.0.1` or `[::1]`, with no port or the bound port (DNS-rebinding guard, rule R5.3). Case-insensitive; IPv6 bracket parsing; rejects tricks like `localhost.evil.example` and `evil.example:8080@localhost`. Failure → 403.
2. **Token check** — every path except `/__kaanal/health` and `/__kaanal/ui` needs `Authorization: Bearer <token>`. `/__kaanal/events` alone may take `?token=` because the browser `EventSource` API cannot set headers (rule R5.2). Comparison is `ct_eq` — constant-time, so the token can't be guessed byte-by-byte from response timing. Failure → 401.
3. **Response hardening** — `Cache-Control: no-store` and `X-Content-Type-Options: nosniff` on every control response.

## Handlers

| Handler           | Route                                    | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `topology`        | `GET /__kaanal/topology`                 | JSON dump: nodes (name/type/flavor; `type` is `NodeKind::as_str()`, e.g. `external-api`), edges (from/to names), sorted route keys.                                                                                                                                                                                                                                                                                                                                                                                                                |
| `get_chaos`       | `GET /__kaanal/chaos`                    | Nested (breaking change from the flat map, Z16): `{ "nodes": {name: view}, "endpoints": {key: view}, "node_at": [{node, endpoint, ...view}] }`, built from `ChaosState::entries()`.                                                                                                                                                                                                                                                                                                                                                                |
| `set_chaos`       | `PUT /__kaanal/chaos/{node}`             | **Merges** a `ChaosPatch` into the node's existing settings (absent fields keep their values). The patch is merged into the node's `ChaosLayer` (`apply_patch`); the merged layer is checked by core's `ChaosLayer::validate` (rule R6.9: `error_rate` 0–1, `error_status` 500–504 for every kind, `latency_ms` ≤ 300 000 — 5 min, `MAX_LATENCY_ADD`) and stored only if valid; a bad patch → 400 and nothing changes. Unknown node → 404; bad body → the extractor's own 4xx. `deny_unknown_fields` rejects typo'd keys. Returns the merged view. |
| `set_chaos_keyed` | `PUT /__kaanal/chaos`                    | Like `set_chaos`, but the body is a `KeyedPatch`: `node?`, `endpoint?` and the patch fields. `node` alone = `Node`, `endpoint` alone = `Endpoint`, both = `NodeAt`, neither → 400. The method of the endpoint key is upper-cased; unknown node or endpoint → 404 (checked against `AppState.endpoints`); an endpoint with no entry node → 400 (defensive: `compile` rejects such configs). A node/endpoint pair is not checked against the chain (a node it never visits never fires).                                                             |
| `clear_node`      | `DELETE /__kaanal/chaos/{node}`          | Removes one node's chaos → 204. Unknown node → 404.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `clear_keyed`     | `DELETE /__kaanal/chaos?node=&endpoint=` | Removes exactly the layer under that key → 204 (also when there was none); no query wipes all chaos (the old `clear_all`). `ClearQuery` denies unknown keys, so a misspelt key is a 400 and wipes nothing.                                                                                                                                                                                                                                                                                                                                         |
| `events`          | `GET /__kaanal/events`                   | SSE stream: every request event as JSON (`event: request`), plus `event: lagged` if a slow subscriber drops messages. Backed by the `broadcast` bus in `AppState`; keep-alive enabled.                                                                                                                                                                                                                                                                                                                                                             |
| `ui`              | `GET /__kaanal/ui`                       | The embedded HTML page (`include_str!`). Served with `Referrer-Policy: no-referrer` and a strict CSP (inline script/style only, `connect-src 'self'`, `frame-ancestors 'none'`). The page reads the token from the URL **fragment**, which browsers never send to a server.                                                                                                                                                                                                                                                                        |

## Supporting items

| Item                                     | What it does                                                                                                                                                                             |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `reject(code, msg)`                      | Builds the uniform `{ "error": msg }` JSON error tuple used by all handlers.                                                                                                             |
| `query_token(query)`                     | Extracts `token=` from a query string; `xtoken=` or a bare `token` do not match.                                                                                                         |
| `ChaosView` / `From<&ChaosLayer>`        | The public JSON shape of chaos (`latency_ms`, `error_rate`, `error_kind`, `error_status`, `down`); unset fields show their defaults.                                                     |
| `ChaosPatch`                             | The accepted PUT body — all fields optional (`error_kind` is a string: `status`, `reset`, `hang`, `malformed`, else 400), unknown fields denied. `layer()` turns it into a `ChaosLayer`. |
| `KeyedPatch`, `ClearQuery`               | Bodies of the keyed routes. `KeyedPatch` repeats the patch fields instead of `#[serde(flatten)]` because flatten would drop `deny_unknown_fields`; keep it in step with `ChaosPatch`.    |
| `apply_patch`, `endpoint_key`, `node_id` | Merge + validate + store one patch under a `ChaosKey`; normalise `METHOD /path`; resolve a node name or 404.                                                                             |
