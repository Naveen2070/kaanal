# `crates/kaanal-server/src/control.rs`

The control API handlers and the security guard that stands in front of them.

## The guard (runs before every `/__kaanal/*` route)

`guard(State, req, next)` — a middleware, so it runs **before any extractor parses a body or query**; unauthenticated callers never reach handler code:

1. **Host check** — `host_allowed(host, port)`: must be `localhost`, `127.0.0.1` or `[::1]`, with no port or the bound port (DNS-rebinding guard, rule R5.3). Case-insensitive; IPv6 bracket parsing; rejects tricks like `localhost.evil.example` and `evil.example:8080@localhost`. Failure → 403.
2. **Token check** — every path except `/__kaanal/health` and `/__kaanal/ui` needs `Authorization: Bearer <token>`. `/__kaanal/events` alone may take `?token=` because the browser `EventSource` API cannot set headers (rule R5.2). Comparison is `ct_eq` — constant-time, so the token can't be guessed byte-by-byte from response timing. Failure → 401.
3. **Response hardening** — `Cache-Control: no-store` and `X-Content-Type-Options: nosniff` on every control response.

## The one write path (S11)

Every handler that changes chaos state does the same three things:

1. `lock(st)` the `Control` mutex (a poisoned lock is recovered with `into_inner`, so one panic does not take the control plane down). The guard is never held across an `.await`; the compiler enforces it because the handler futures must be `Send`.
2. `commit(st, &mut guard, |control| ...)`: back up `Control`, run the closure, then `AppState::publish` (compile, check, swap the `Arc`). On an error from either, the backup is put back, so a bad request changes nothing. A panic is not caught: the half-written `Control` would be compiled by the next write, while the request path keeps the last published `Arc`.
3. Answer from the `Arc<Effective>` that `commit` returned (exactly what was published) and `emit` a scenario event where the stack changed.

Only writers and the two scenario GETs (`list_scenarios`, `get_scenario`, whose data lives in the set) take the mutex. The request path and the other GETs read the snapshot.

## Handlers

| Handler           | Route                                        | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `topology`        | `GET /__kaanal/topology`                     | JSON dump: nodes (name/type/flavor; `type` is `NodeKind::as_str()`, e.g. `external-api`), edges (from/to names), sorted route keys.                                                                                                                                                                                                                                                                                                                                      |
| `get_chaos`       | `GET /__kaanal/chaos`                        | The **live layer** only, nested (Z16): `{ "nodes": {name: view}, "endpoints": {key: view}, "node_at": [{node, endpoint, ...view}] }`, plus `"effective"` (the compiled result of the scenarios and the live layer; calm keys are omitted). `mode: "override"` shows on an overriding entry.                                                                                                                                                                              |
| `set_chaos`       | `PUT /__kaanal/chaos/{node}`                 | Merges a `ChaosPatch` into the node's live layer (absent fields keep their values, `mode` included). The merged layer is checked by core's `ChaosLayer::validate` (R6.9) and stored only if valid; a bad patch → 400 and nothing changes. Unknown node → 404; bad body → the extractor's own 4xx. `deny_unknown_fields` rejects typo'd keys. Answers the stored layer's `ChaosView` plus `effective` and `warnings` (see `apply_patch`).                                 |
| `set_chaos_keyed` | `PUT /__kaanal/chaos`                        | Like `set_chaos`, but the body is a `KeyedPatch`: `node?`, `endpoint?` and the patch fields. `node` alone = `Node`, `endpoint` alone = `Endpoint`, both = `NodeAt`, neither → 400. The endpoint goes through core's `endpoint_key` (method upper-cased; a malformed one → 400); unknown node or endpoint → 404; an endpoint with no entry node → 400. A node/endpoint pair is not checked against the chain (a node it never visits never fires).                        |
| `clear_node`      | `DELETE /__kaanal/chaos/{node}`              | Removes one node's **live** layer → 204. Unknown node → 404. Scenarios stay.                                                                                                                                                                                                                                                                                                                                                                                             |
| `clear_keyed`     | `DELETE /__kaanal/chaos?node=&endpoint=`     | Removes exactly the live layer under that key → 204 (also when there was none); no query wipes the live layer only (S12). `ClearQuery` denies unknown keys, so a misspelt key is a 400 and wipes nothing; a malformed endpoint is 400.                                                                                                                                                                                                                                   |
| `list_scenarios`  | `GET /__kaanal/scenarios`                    | Array of `{ name, source (inline\|file\|runtime), description, entries, active }`, in definition order.                                                                                                                                                                                                                                                                                                                                                                  |
| `get_scenario`    | `GET /__kaanal/scenarios/{name}`             | `{ name, source, description, chaos: [...] }` with sparse entries (`layers_json`), the same shape a file holds. 404 if unknown.                                                                                                                                                                                                                                                                                                                                          |
| `put_scenario`    | `PUT /__kaanal/scenarios/{name}`             | Defines or replaces a **runtime** scenario. The body is a `ScenarioConfig` (`description?`, `chaos: [...]`), resolved by core's `resolve_scenario` exactly as a file would be. Answers `{ name, warnings }`. 400 for a bad name or entry (message placed as `chaos[2].node: ...`), 404 for an unknown node or endpoint (`ScenarioError.not_found`), 409 when the name comes from the config or a file. Replacing an active scenario re-compiles and emits `update`.      |
| `delete_scenario` | `DELETE /__kaanal/scenarios/{name}`          | Undefines a runtime scenario (S19), prunes it from the stack and emits `deactivate` if it was active. 404 unknown, 409 inline or file.                                                                                                                                                                                                                                                                                                                                   |
| `activate`        | `POST /__kaanal/scenarios/{name}/activate`   | Pushes (or moves) the scenario to the top of the scenarios. Answers `{ active, effective }`. 404 if unknown.                                                                                                                                                                                                                                                                                                                                                             |
| `deactivate`      | `POST /__kaanal/scenarios/{name}/deactivate` | Removes it from the stack; 204, also when it was not active (no write, no event then).                                                                                                                                                                                                                                                                                                                                                                                   |
| `set_active`      | `PUT /__kaanal/scenarios/active`             | Body `["a","b"]` sets the whole stack bottom to top, all or nothing (an unknown name → 404, nothing changes). Answers like `activate`; emits `set`.                                                                                                                                                                                                                                                                                                                      |
| `get_active`      | `GET /__kaanal/scenarios/active`             | `{ active, effective }` of the published snapshot.                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `clear_scenarios` | `DELETE /__kaanal/scenarios`                 | Deactivates every scenario; the live layer stays (S12). 204; emits `clear`.                                                                                                                                                                                                                                                                                                                                                                                              |
| `reset`           | `POST /__kaanal/reset`                       | Clean slate (S18): deactivates all, undefines the runtime-defined scenarios (inline and file ones stay), clears the live layer, zeroes `AppState.counters`, refills the engine's rate-limit buckets (`EngineHandle::refill_buckets`; gates and pools are not reset). Counters and buckets are touched only after the publish succeeded. 204; emits `reset`. Requests in flight are not interrupted.                                                                      |
| `save_scenario`   | `POST /__kaanal/scenarios/save`              | Writes `scenarios/NAME.yaml` from `from` (`SaveFrom`: `"live"` default, `"effective"`, `{"scenario": name}`), registers it as a file scenario, optionally clears the live layer. Answers `{ name, path }`. See [../../chaos.md](../../chaos.md#save-s17) for the refusals; the status codes are 400 (bad name, inline name, nothing to save, override, unsaveable `effective`), 404 (unknown source scenario), 409 (exists without `force`), 422 (bad `from`), 500 (IO). |
| `events`          | `GET /__kaanal/events`                       | SSE: `event: request` for every finished request, `event: scenario` (`{ action, name, active }`) for stack changes, `event: lagged` if a slow subscriber drops messages. Backed by the `BusEvent` broadcast bus; keep-alive enabled.                                                                                                                                                                                                                                     |
| `ui`              | `GET /__kaanal/ui`                           | The embedded HTML page (`include_str!`). Served with `Referrer-Policy: no-referrer` and a strict CSP (inline script/style only, `connect-src 'self'`, `frame-ancestors 'none'`). The page reads the token from the URL **fragment**, which browsers never send to a server. It shows the live layer only (M2 adds a scenario panel) and ignores `scenario` events.                                                                                                       |

## Supporting items

| Item                                                                      | What it does                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `reject(code, msg)`                                                       | Builds the uniform `{ "error": msg }` JSON error tuple used by all handlers.                                                                                                                                                                                                                                                                                          |
| `query_token(query)`                                                      | Extracts `token=` from a query string; `xtoken=` or a bare `token` do not match.                                                                                                                                                                                                                                                                                      |
| `ChaosView` / `From<&ChaosLayer>`                                         | The public JSON shape of one stored layer (`latency_ms`, `error_rate`, `error_kind`, `error_status`, `down`, and `mode: "override"` only when set); unset fields show their defaults. Built with core's `merge` on a single layer.                                                                                                                                    |
| `ChaosPatch`, `parse_mode`                                                | The accepted PUT body — all fields optional (`error_kind`: `status`, `reset`, `hang`, `malformed`, else 400; `mode`: `merge` or `override`, else 400), unknown fields denied. `layer()` turns it into a `ChaosLayer`. An absent `mode` leaves the stored value, `merge` stores `Some(false)`, `override` stores `Some(true)`.                                         |
| `KeyedPatch`, `ClearQuery`                                                | Bodies of the keyed routes. `KeyedPatch` repeats the patch fields instead of `#[serde(flatten)]` because flatten would drop `deny_unknown_fields`; keep it in step with `ChaosPatch`.                                                                                                                                                                                 |
| `apply_patch`                                                             | Under `commit`: merge the patch into the stored live layer, validate it, store it (a bare `mode: merge` on a key with no entry stores nothing; a bare `mode: override` stores an empty layer, which calms the key). The answer carries `effective` and `warnings`: `warnings` is non-empty when the stored layer has a kind or status without a rate, naming the key. |
| `lock`, `commit`, `emit`                                                  | The write path above, and the scenario event sender.                                                                                                                                                                                                                                                                                                                  |
| `keyed_json`, `resolved_json`, `effective_json`, `active_json`, `is_calm` | JSON builders. `effective_json` places each compiled key under `nodes` / `endpoints` / `node_at`; a key is `{ latency_ms, down, faults: [{ upto, kind, status }] }`; a **calm** key (no latency, not down, no faults, for example after a live override) is left out.                                                                                                 |
| `layers_json`, `key_fields`, `key_label`                                  | Sparse YAML-shaped entries of a layer set (only fields that are set), and node/endpoint naming.                                                                                                                                                                                                                                                                       |
| `effective_entries`                                                       | `save` with `from: effective`: the compiled keys as entries. Refuses (400 naming the key) a key with two or more failure bands and a node@endpoint pair whose node also has non-calm chaos.                                                                                                                                                                           |
| `SaveFrom`, `SaveBody`                                                    | Strict body of `save`: `SaveFrom` accepts only `"live"`, `"effective"` and `{"scenario": "<string>"}` (`try_from = Value`, so `{"live": null}`, extra keys or a bare name give 422 "from must be ...").                                                                                                                                                               |
| `place`, `unknown`, `source_name`                                         | A `ScenarioError` path as `chaos[2].node: msg`; the 404 for a scenario name; `inline`/`file`/`runtime`.                                                                                                                                                                                                                                                               |
| `node_id`                                                                 | Resolves a node name or 404. The key normalizer is core's `endpoint_key`; the private copy in this file is gone.                                                                                                                                                                                                                                                      |
