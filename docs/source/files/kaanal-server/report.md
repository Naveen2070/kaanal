# `crates/kaanal-server/src/sim/report/`

The sweep report (Step 9b): one finished sweep record turned into a Markdown document that ends in a fenced JSON block holding the same data. A person reads it cold; an agent parses the JSON block. The server is the only maker of these bytes: the report route, the CLI and Studio hand them over unchanged (no second renderer, no wording shared with the CLI except through the JSON).

## What it does

`sweep_report(rec, version)` reads one `RunRecord` (see [sim.md](sim.md)) and returns `SweepReport { markdown, json }`. `version` is the `kaanal` version the recipe names (`env!("CARGO_PKG_VERSION")` at the call site). It refuses, never panics:

| Record                                                                                                                     | Error                     |
| -------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| `kind` is `run`                                                                                                            | `NotAReport`              |
| `state` is `running`                                                                                                       | `Running`                 |
| `state` is `failed`                                                                                                        | `Failed(error)`           |
| done, but no `sweep`, `seed`, `max_factor` or `fingerprint`, or no `live_chaos` without a `scenario`, or no `chaos_digest` | `Internal(field)` (a bug) |

**The JSON** (`report_version` 1; keys sorted, as `serde_json`'s map keeps them): `label`, `id`, `finding` (`verdict`, `limit { p99_ms, error_rate }`, `first_to_saturate`, `dominant_cause`, `recovers_at`, `stopped_at`, `warnings`), `points` (from `sweep.points`, sorted; per-node data left out, so the report names only the nodes its finding mentions) and `recipe` (`command`, `seed`, `max_factor`, `profile`, `inline_profile`, `scenario`, `fingerprint`, `chaos` (`none`, `scenario` or `live`), `live_chaos` (the record's, `null` under a scenario), `chaos_digest`, `runtime_scenarios`, `generation`, `kaanal_version`).

**The Markdown**, in order: `# Load sweep <id>`; the label in italics; `## Finding` (the verdict in the CLI's words: `knee at N req/s (Kx), the last point within the limit; the next point is over: ...` with what the next point crossed (the knee is the last passing point), `over the limit already at the lowest point, ...`, `holds to ...` or, for a cut ladder (`stopped_at`), `held to ..., the last point run (the ladder stopped above it)`; then the limit, the first node to saturate with its analytic figure, the dominant cause, `Chaos in force:` (`none`, `scenario NAME`, or `live chaos: [active scenarios a, b; ]N entries, digest X`), `Chaos digest:` (the record's `chaos_digest`) and the warnings); `## Curve` (`load req/s | goodput | p99 ms | errors | ok`, `ok` naming which limit a point is over); `## Re-run` (a `bash` block: the command; under live chaos a `# live chaos in force when this ran (...): the command alone cannot reproduce it; activate the same chaos first` line; a `# scenarios defined at runtime in force (...)` line when `runtime_scenarios` is not empty; comments for the seed, the fingerprint (it does not cover the chaos: the same fingerprint, chaos digest and seed mean the same numbers, the fingerprint alone does not) and the version); `## Data` (the JSON, `serde_json::to_string_pretty`, with format characters and U+2028/U+2029 written as `\u` escapes).

**The command.** `kaanal sim sweep --profile=NAME --p99 <humantime> --errors <pct>% --max-factor M --seed S [--scenario=NAME]`; the `=` form keeps a name that starts with `-` a value. An inline profile (`inline_profile` set; a config profile may itself be named `inline`) gives `-f profile.yaml`, and the profile is in `recipe.inline_profile` (JSON is YAML, so it can be saved as that file). `--errors` prints the share x 100 to nine decimals with trailing zeros cut, so `0.07` gives `7%`, not `7.000000000000001%`.

**Hostile names.** Node, profile and scenario names come from the user's files. `clean` drops control characters, Unicode format characters (General_Category Cf: bidi overrides and isolates, zero-width spaces; the Trojan Source attack, CVE-2021-42574) and U+2028/U+2029 (Zl, Zp: line breaks to some renderers), all of which the CLI's `clean_lines` would print as `?`; so the server's bytes pass the CLI unchanged and `sim report`, the route and Studio's Save are byte-identical. In the prose, `text` cleans a name, backslash-escapes the backslash, the backtick and `* _ [ ] < > | ~ &` (CommonMark 0.31 section 2.4; `|` and `~` for GFM tables and strikethrough), and escapes a leading block marker (`#`, `+`, `-`, `=`, or 1 to 9 digits then `.` or `)`), so a warning cannot open a heading, list or quote inside its list item. In the command a name is cleaned and POSIX single-quoted (XCU 2.2.2) unless it is all `[A-Za-z0-9._-]`, so no line in the `bash` fence can start with a fence. In the JSON fence names go through `serde_json`, which escapes every control character (RFC 8259), and `json_text` writes format characters as `\u` escapes (it still parses back to the same value); a pretty-printed line never starts with a backtick, so it cannot close the fence (CommonMark section 4.5). The table holds only numbers and fixed words.

## The plan report (Step 9c-1)

`plan_report(rec, version)` (in `report/plan.rs`) does the same for a finished record of kind `plan`, and `report(rec, version)` picks the maker by `kind` (the report route calls it). It uses the same helpers (`text`, `clean`, `shell`, `json_text`, `Chaos`, the re-run block `rerun`), so hostile names, the chaos digest, the fingerprint sentence and the `## Re-run` / `## Data` fences behave as the sweep's; the sweep golden files did not change. A plan record that is a `run` or `sweep` is `NotAReport`; `Running`, `Failed` and `Internal(field)` (no `plan`, `seed`, `fingerprint`, `live_chaos` without a scenario, `chaos_digest`, or a `target` with neither `multiple` nor `req_s`) as for a sweep.

**The JSON** (`report_version` 1): `label`, `id`, `plan` (the record's `PlanDoc` as the record serves it: `request`, `verdict`, `steps` with their menus, `start`, `end`, prices in micro-USD an hour, `unpriced_nodes`, `families`, `verify`, `measured_knee`, `sweep_error`) and `recipe` (`command`, `seed`, `profile`, `inline_profile`, `scenario`, `fingerprint`, `chaos`, `live_chaos`, `chaos_digest`, `runtime_scenarios`, `generation`, `kaanal_version`). The proposed draft is not in it: it is served by `GET /runs/{id}/draft`.

**The Markdown**, in order: `# Sizing plan <id>`; the label in italics; a paragraph that says the plan is not a prediction, that prices are estimates and that Kaanal does not apply it; `## Target` (offered req/s and the factor on the profile's rates, the limit and the margin rule, budget, kept nodes, step cap); `## Now` (the design in force at the target and its price); `## Plan` (a table of the steps: node, change, price delta and total, capacity estimate, p99 and errors before and after, each labelled; a step's note; the design the plan ends in); `## Menu` (every move the walk tried per step, the taken one marked, with price, effect and whether it holds); `## If you changed the database family` (each answer with its verdict in words, its steps and end figures and its notes, which carry "assumes your application can use this family; preset estimates"; a skipped database or flavor with its reason); `## Verdict` (all six `PlanVerdict` cases in plain words, `cannot_hold` naming the node and reason, `over_budget` saying by how much and whether the design it stops at holds, `no_progress` saying the last two steps gained nothing (the second on the named node: the two may be on different nodes, so nothing is claimed about sizing it further); unpriced nodes named); `## Checked` (the re-check of the proposed draft, its cost with per-use prices and the `cost_note` for a design that does not hold, the measured knee, worded as a search result on the plain limit (no margin), or why the sweep did not run); `## Re-run`; `## Data`. The `## Verdict` section adds the **budget check** line from `PlanDoc.budget_check` (`budget_line`: what the plan shown costs with per-use prices, within or over the budget and by how much, and a sentence when those prices turned `holds` into `over_budget`); an `over_budget` with `holds: false` says no holding design was found within the budget and gives the shown plan's price without per-use prices, never "within the budget". A family answer at its step cap names `FAMILY_MAX_STEPS`.

**Money** is whole micro-USD shown with integer arithmetic (`dollars`: `840000` is `0.84`, `3500` is `0.0035`), never through a float. **The margin rule** for a family answer's end design is `holds_with_margin`, the rule of `Limit::passes_with_margin` on an `Effect` (a test holds the two to the same answers). **The command**: `kaanal sim plan --profile=NAME --target=2.5x|500 --p99 <humantime> --errors <pct>% [--budget=2.00] [--keep=NODE]... --max-steps N --seed S [--scenario=NAME]` (`-f profile.yaml` for an inline profile).

## The cheapest plan's report (Step 9c-2)

`report/plan_cheapest.rs` (a child of `report`, called by `plan_report` only for a plan with `search` set; a plain plan's bytes do not depend on it, and the 9c-1 golden still matches) writes, in order: the label `*cheapest found within the limit, not proven cheapest*` under the plan's own label (`label`); **`## Search`** (`search`: why the main search stopped in words, runs of the run cap, time used of its share of the limit, the candidates refused for size, a "could cost less" sentence with both prices when the design in force held and the plan ends cheaper, and the monotonicity assumption); **`## Comparison`** (`comparison`, left out when no provider section ran: a table of the design in force and each provider answer with its price an hour, whether it holds and how it ended; designs that hold are ranked cheapest first and the winner is named with the label, "(tied with ...)" on equal prices; none holding says "No design holds at any size tried, so there is no winner."; a skipped provider is listed under "Not compared" with its reason); **`## Plan`** (`changes`: a table of the changes with each one's own price effect and note, then the start and the end with their prices; never a running price, because the search merges the moves of one knob of one node, so `steps[i].after` is not `steps[i+1].before`); the menu only when a step has one; no database-family section (a cheapest plan has none); **`## Verdict`** through `words`, which knows a limit cut the search: a design that does not hold after a run cap or time limit says "No design that holds the target was found within the limit ... That does not show that none exists", never "cannot hold", and an `already_holds` says no cheaper design was found within the limit and, when cut, that one may exist; then `## Checked`; then **one `## If it ran on GCP`-style section per provider answer** (`sections`: the label, "This what-if assumes wires, egress, data location and application are unchanged; on-demand price estimates.", the verdict in words, its budget check or per-use cost line and `cost_note`, its search lines, the translation's notes (the nodes "kept as written, not compared"), the changes table and the translated design's start and end; no translated draft); the re-run recipe adds `--cheapest --time=Ns --run-cap=N --providers=gcp,azure|none` (`flags`). Money is the `dollars` of `plan.rs`, so a saving under a cent prints as `$0.0035/h`, never `$0.00`. `plan.rs` makes `dollars`, `price`, `effect`, `change`, `verdict_words` and `budget_line` `pub(super)` for it.

## Tests

Unit tests in `sim/report/tests.rs` (moved out of `mod.rs` on 2026-11-21 for the file-size rule: the code and its tests were 735 lines together; a child module, so it reads the private helpers without any change in visibility). `the_report_matches_the_golden_file` pins the bytes against `tests/golden/sweep-report.md` (a three-point knee record; read with `include_str!`; excluded from `dprint` in `dprint.json` so a formatter never rewrites it) and checks the JSON block equals `to_string_pretty` of the returned `json`. Others: the JSON block parses back to `json`; refusals (`Running`, `Failed` keeping the message, `NotAReport`, `Internal` for each missing field); the label is the first line after the heading and a JSON field; an inline profile gives `-f profile.yaml` and is embedded; a config profile named `inline` stays `--profile=inline`; a name starting with `-` stays a value (`--profile=-x`); a warning starting with a block marker is escaped; format characters are stripped; a tiny limit is not `0%`; the limit formats (`500ms`, `1s`, `'1s 500ms'`, `2%`, `0.5%`, `7%`); a cut ladder says `held to`, not `holds to`; a node, profile and scenario holding a backtick, a pipe, a newline, a fence, a bell and a bidi override keep the table's columns, the fences closed, the JSON parsable and no control or format character in the text. Added 2026-11-21: the knee sentence names the last point within the limit and the next point's crossing; no chaos, a named scenario and live chaos each give their `Chaos in force` line, fingerprint comment, recipe line and JSON fields (`tests/golden/sweep-report-live-chaos.md` pins the live variant); a U+2028/U+2029 in a node, profile or scenario name leaves nothing the CLI would change, and is `\u` escaped in the JSON.

Cheapest report tests: `sim/report/plan/cheapest_tests.rs` (a child of `plan`; `tests/golden/plan-report-cheapest.md` pins a hand-built cheapest plan with a winner, a skipped provider and a saving under a cent; the winner, ties, no winner when nothing holds, each stop reason's words and a cut that never says "cannot hold", a skipped provider, the section's caveat, label and budget verdict, a tiny saving, "could cost less", no price sequence for collapsed steps, the JSON block, the recipe flags, hostile names, and the plain report unchanged).
