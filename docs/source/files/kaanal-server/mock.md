# `crates/kaanal-server/src/mock.rs`

The mock request handler — the axum fallback that serves every non-control route.

## What it does

`handle(State, req)` turns one HTTP request into a mocked response, end to end:

1. **CORS** — preflight (`OPTIONS`) returns 204 with permissive headers. The `/__kaanal` namespace never gets CORS, not even on a 404 (rule R5.4).
2. **Routing** — `matchit` lookup by path; 404 `{"error":"no route"}` on miss. Within a matched path, only the exact method matches. A `HEAD` with no entry of its own finds the `HEAD` copy `compile` made from `GET` (own key and counter, rule R6.8; hyper strips the body). No method → 405.
   2a. **Scope** — `scope_of` reads `X-Kaanal-Scenario` (after the 404/405 checks, so they ignore it; before the login body and the counter, so a bad header costs no draw). A bad header is `400 {"error":"bad scenario scope","detail":...}` with CORS. A good one gives the stack key and its compiled `Scoped` from the cache ([scope.md](scope.md)); no header gives `None`.
   2b. **Login body** — a route whose responder is `Login` and that has no `override` has its body read now, before the chain (`auth::read_login`; no sleep yet), so a bad body still costs the full chain latency. An `override` replaces the responder, so its body is never read.
3. **Plan** — builds a `ChainRequest` (the route's compiled `Endpoint`; per-route atomic counter `n`; `AppState.chain_seed`) and calls `kaanal_core::sample_plan` **in the handler** (microseconds of pure math). `plan_of` samples the whole plan from a scoped request's cached `Scoped.chaos` or, without a header, from one `AppState::snapshot()` (an `Arc<Effective>` clone, S10) and its compiled `EffectiveChaos`; the snapshot is dropped before the next await, so a swap mid-request never reaches this request, and no lock or mutex is held on the request path.
4. **Engine** — `AppState.engine.run(plan)` hands the plan to the engine actor ([actor.md](actor.md)), which runs it in real time through the shared queues, pools and rate limits and answers with a `Finished` (result, per-hop waits). The client waits the real simulated time. A stopped engine answers 500 `{"error":"engine stopped"}`. (Windows caveat: the answer wakes on the OS timer tick, about 15 ms; hops still start at their scheduled times, so the trace stays exact while measured latency can exceed it.)
5. **Response shaping** — on `ChainResult::Err`, a **wire failure** comes first: `reset` or `malformed` at a wire node (`Endpoint::is_wire_node`: gateway or owner), unless the `error_map` has a node or kind key for it, is served by `wire_failure` (below). Otherwise `resolve_error` looks the failure up in the endpoint's `error_map` (node name, then failure kind, then exact status, then class such as `5xx`); with no match the kind's default status (own status, reset/malformed 502, timeout 504) and `default_error_body` (`{"error":"chaos","node":name}`, plus `"kind"` for a non-status kind) are used. A `timeout` at a wire node is not a wire failure: it stays remappable. A final status of **429** from a rate limit carries `Retry-After` (whole seconds, rounded up, at least 1); an `error_map` that changes the status drops it. Precedence: chain failure (through `error_map`) > `override` > built-in responder (413/415/400, then 401 or 200; the JWKS is 200; a JWKS `HEAD` answers through its synthesized copy) > generated body. On `Ok`: the endpoint's `override` (status and body) if it has one, else the responder's answer (`auth::respond`), else `kaanal_data::generate` seeded by `stable_hash(seed, node, path)` (same `seed:` + URL → same body forever; a new `seed:` reshuffles the data; the chain seed is not involved), then `apply_params` copies path params into matching fields.
   5a. **No-store** — every response of a `Login` route (including chain failures and an `override`) gets `Cache-Control: no-store` and `Pragma: no-cache`. The JWKS does not.
   5b. **Scope echo** — a scoped response gets `X-Kaanal-Scope: <names joined by ,>` (the deduplicated stack; an empty header echoes an empty value). No header, no echo. `with_cors` exposes it.
6. **Trace header** — `X-Kaanal-Trace` (built by `trace_header`): the visible hops in plan order with one decimal (`nginx.proc=1.0ms,net=1.0ms,db.read=1.0ms`); cache lookups print `cache.hit=` or `cache.miss=`; a hop that queued is preceded by `node.wait=T` (for example `app.proc=2.0ms,net=1.0ms,db.wait=98.0ms,db.read=100.0ms`; none at zero load, and a wait piece counts as a hop in `...+N hops`); a `parallel` block is bracketed with `|` between branches, e.g. `nginx.proc=1.0ms,net=0.0ms,app.proc=2.0ms,[net=0.0ms,audit.proc=1.0ms|net=0.0ms,pay.proc=4.0ms],net=0.0ms,c.hit=0.2ms`; a failure appends `node.error=STATUS` (the real failure, even when `error_map` changed the response status), or `node.error=reset` / `malformed` for those kinds; an endpoint `Delay` hop prints `entry.delay=`. Branches a failure cancelled show only what they ran before the failure instant (a branch that never started is empty). The value is capped at 4096 bytes: past that it stops before a hop, closes any open `[`, and ends `,...+N hops` with N the pieces left out, wait pieces included (ASCII, D13); the error part is always kept.
7. **Event** — sends a `BusEvent::Request(Event)` (timestamp, method, path, status, **measured** wall ms, ordered unique node names, failing node, `kind`, and `scope`: `None` without the header, `Some(key)` with it) on the broadcast bus for SSE subscribers. No subscribers = send error, ignored by design.

## Wire failures (B2a)

`wire_failure` serves a `reset` or `malformed` at a wire node. Both start from the real reply (`answer()`: responder or success body, so the JWKS is cut as the JWKS) and the route's success status:

- **malformed** — the serialized body cut at about half at a char boundary, `Content-Type: application/json`, correct `Content-Length`: valid HTTP, invalid JSON.
- **reset** — `wire::Cut` streams one chunk, then breaks; `Content-Length` is the full length (at least chunk + 1), so the client has the status line and part of the body and then sees the connection abort ([wire.md](wire.md)).
- **Nothing to cut.** No body, or HEAD / 204 / 304 (hyper strips the body): the plain success response; the trace still ends `error=reset|malformed`. A body-less success route (`null`) breaks as `{}`.
- The event's status is the status actually sent.
