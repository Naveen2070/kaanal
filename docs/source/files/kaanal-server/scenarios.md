# `crates/kaanal-server/src/scenarios.rs`

Scenario files: `scenarios/NAME.yaml` next to `kaanal.yaml`. The only place that touches the disk for scenarios; the rules about what a scenario may hold live in [../kaanal-core/scenario.md](../kaanal-core/scenario.md).

## What it does

- **Reads** every scenario file at startup (`discover`, called by `state::load_scenarios`).
- **Writes** one file for `POST /__kaanal/scenarios/save` (`write`, called by `control::save_scenario`).

## Items

| Item                            | Kind | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `discover(dir)`                 | fn   | Reads every scenario file in `dir`, sorted by name, and returns `((name, parsed ScenarioConfig, path), warnings)`. Only regular `*.yaml` files count. **Silent skips:** subdirectories, dotfiles, editor temp files (`*~`, `.#*`). **Skipped with a warning:** symlinks (not followed), names that look like scenario files but do not end in exactly `.yaml` (`.yml`, `.YAML`), names that are not UTF-8, entries whose type cannot be read. An absent `dir` means no files. **Errors (placed in the file where there is one):** an unreadable directory or file, a file over 1 MiB, content that is not UTF-8, a stem that is not a valid scenario name (`valid_name`), more than 128 files, a parse error with `line:col`. |
| `read` _(private)_              | fn   | The file as text, reading at most 1 MiB + 1 byte (`take`) so an oversized file is refused without being read in full (R1.30). Exactly 1 MiB is accepted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `plain` _(private)_             | fn   | Strips the `\\?\` prefix Windows `canonicalize` adds, for messages and path comparison.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `write(dir, name, yaml, force)` | fn   | Writes `NAME.yaml` into `dir` and returns its path. See below.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `WriteError`                    | enum | `Exists` (no `force` and the file exists: the handler answers 409) or `Other(msg)` (500).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `sync_dir` _(private)_          | fn   | `fsync` of the directory entry on Unix; a no-op on Windows (no directory fsync). Best effort.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

## How `write` stays safe (S17)

- `dir` is `AppState.scenarios_dir`, the canonical directory found at startup. `write` creates it if missing and checks that the resolved parent of the target equals it (a directory swapped in since startup is refused). The check-then-use window is documented: a local user who owns the directory could still race it.
- **No `force`:** `OpenOptions::create_new` (so two saves cannot both win, and a symlink at the target is not followed), then `write_all`, `sync_all`, directory sync. A failed write removes the half-written file.
- **`force`:** the text goes to `.NAME.tmp` in the same directory, then `rename` over the target (which replaces a symlink at the target rather than following it). A file or symlink planted at the temp path is **removed first** (the link itself, never its target), and the temp is then made with `create_new`; the temp is `fsync`ed before the rename. On any error the temp is removed.
- Two processes saving the same name at once share the temp path: one may fail with a 500; the target is never half-written. On Windows a target held open by another program makes the rename fail (500). Either way no data is lost.
